TC PIPELINE · 3세대 엔진

tc-team 설계, 아주 쉽게

딱 한 줄만 기억하면 됩니다 — "글은 AI가 쓰고, 틀과 검사는 기계가 한다."

나머지 전부는 이 한 줄을 지키기 위한 장치입니다.

1핵심 원칙 — 2레인 (일을 두 종류로 쪼갠다)

tc-team의 모든 단계는 아래 둘 중 하나입니다. 헷갈리면 "이건 문장 쓰는 일인가, 장부 다루는 일인가?"만 물어보면 됩니다.

🤖 AI 레인 — 문장과 판단

  • 기획서를 읽고 TC를 설계한다
  • 재현스탭 문장을 쓴다 (F열)
  • 리뷰하고 "여기 고쳐라" 의견을 낸다
  • 기획서 규칙 ↔ TC를 의미로 짝짓는다
  • 행 번호 매기기 · 개수 세기 · 서식
  • 시트에 직접 쓰기
AI는 숫자·구조를 만들 권한이 없습니다. 골격이 준 빈칸만 채웁니다.

⚙️ 기계 레인 — 틀과 사실

  • TC 표의 골격(행·번호·구조) 생성
  • 검문소(게이트) 검사 전부
  • 커버리지 장부(원장) 대조
  • 시트 기록 — 전 과정에서 딱 1번
  • 문장 창작
"결정론" = 같은 입력이면 언제나 같은 결과. 기분 따라 달라지는 게 없는 스크립트.
왜 이렇게 쪼갰나? AI는 훌륭한 작가지만 덜렁대는 사무원입니다. v2에서는 AI가 표를 옮겨 적다 있지도 않은 숫자를 지어내는 사고(발명수치)가 났습니다. 그래서 v3는 AI 손에서 장부를 뺏고 펜만 쥐여줬습니다. 결과: 발명수치 0건, 속도 2.2배.

2내가 아는 v2와 뭐가 다른가

구조를 직접 잡으신 v2를 기준으로 보면 차이는 딱 세 가지입니다.

tc-v2 (내가 만든 구조)tc-team (v3)
일하는 방식팀장 AI가 팀원 AI를 릴레이로 호출메인 세션이 기계 부품과 AI를 순서대로 돌리는 공정 관리자
시트 접촉먼저 쓰고 → 리뷰하며 시트를 계속 수정로컬 파일에서 전부 완성 → 검사 통과 → 딱 1번 기록
리뷰 방식리뷰어가 시트를 직접 고침리뷰는 수정 목록(fix_plan)만 작성, 반영은 기계가
숫자·구조AI가 직접 다룸 → 가끔 사고기계 소유 → 발명수치 0
추적리뷰 보고서로 사후 확인기획서 규칙마다 "어느 TC가 됐나" 장부(원장)가 남음

3전체 그림 — 4막 8단계 (출판사 비유)

기획서 = 저자의 원고, 시트 = 인쇄된 책이라고 생각하면 전 과정이 출판사입니다.
기억법: 받고 → 짜고 → 채우고 → 다듬고 → 찍고 → 진열

1막 재료 준비

S0원고 접수 ⚙️ 메인

Confluence 기획서를 원문 그대로 복사해 보관하고, 제대로 다 받았는지 3가지 자가검사(크기·이미지 개수·잘림 흔적)를 합니다. 동시 실행 방지 잠금도 여기서.

인쇄소가 원고를 받자마자 페이지 수부터 센다. 원고가 덜 왔으면 작업 시작 자체를 안 한다.

S1편집 구성안 🤖 AI

기획서를 읽고 분석서(analysis.md)와 TC 설계도(tc_design.md)를 만듭니다. v2에서 다듬은 설계 노하우를 그대로 승계한 단계입니다.

편집자가 원고를 읽고 목차와 챕터 구성을 짠다.
2막 조립

S2구성안 검사 + 원고 자르기 ⚙️ 기계

설계도가 기계가 전개할 수 있는 형식인지 검사하고(불합격이면 S1로 반려), 기획서 원문을 문단 단위로 잘라 번호를 붙입니다. 이 번호가 나중에 "이 규칙이 어느 TC가 됐나" 추적하는 기준점이 됩니다.

원고에 형광펜으로 문단 번호를 매겨둔다 — 나중에 대조하려고.
설계 결함이면 S1로 돌려보내 다시 설계.

S3골격 + 문장 채우기 ⚙️ 골격·합치기 🤖 문장만

기계가 TC 표의 골격(행·번호·구조)을 먼저 만들고, AI 여러 명이 25행씩 나눠 빈칸(재현스탭 문장)만 동시에 채웁니다. 기계가 다시 합치면서 "자기 행에 제대로 채웠나"를 검사합니다.

조판 틀은 기계가 짜고, 작가들은 정해진 빈칸에 글만 써넣는다. 남의 칸을 건드리면 그 조각만 다시 쓰게 한다.
어긋난 25행 조각만 재실행 — 나머지는 그대로 살린다.
3막 검사

S4빨간펜 3인 + 심판 🤖 AI

교정자 3명이 서로 다른 눈(구조 / 품질 / 원문대조)으로 병렬 검토하고, 심판이 서로 반박시켜 살아남은 지적만 수정 목록(fix_plan)으로 만듭니다. 직접 고치지 않는 게 핵심. 동시에 원장도 작성: 기획서 규칙 하나하나가 어느 TC에 반영됐는지 짝짓고, 뺀 것은 사유를 남깁니다.

교정지에는 빨간펜만. 원고에 손대는 건 다음 단계의 조판공이다.

S5수정 반영 + 최종 검문 ⚙️ 기계

수정 목록을 기계가 반영합니다. 단, 고치려는 원문이 지금도 그대로일 때만(다르면 거부 — 거부가 정상 동작입니다). 이후 3중 검문: 금지표현 0건, 그룹 연속성, 그리고 원장 대조 — 기획서 규칙 중 TC 없는 게 있으면 자동으로 행을 추가해 봉합합니다.

최종 교정쇄에 승인 도장. 도장 없으면 인쇄기는 안 돈다.
반영 거부 = fix_plan을 다시 만들면 됨. 시트는 아직 깨끗하니 부담 없음.
4막 출고

S6인쇄 — 시트 기록 ⚙️ 기계 시트 접촉 1회

전 검문 통과 후 시트에 딱 1번 기록합니다. 소유마커로 내 탭만 건드리고, 남의 탭이면 _v2 접미사로 새로 만듭니다. 기록 직후 시트를 다시 읽어 원본 파일과 한 글자도 다르지 않은지(0-diff) 확인합니다.

인쇄 후 첫 권을 뽑아 원고와 나란히 놓고 대조한다.

S7서점 진열 — 완료처리 ⚙️ 기계

대시보드 갱신 → K~O 정보 패널 → 기획확인 라벨 → 드라이브 백업 → 잠금 해제 → 단계별 시간 포함 완료 보고. 테스트 데이터 라벨링과 이미지 매칭은 필요할 때만 수동(안내 1줄만, 07-27 변경).

서점 진열대에 올리고, 창고 정리하고, 문 닫고 퇴근.

4원장(커버리지 장부) — "빠뜨림"을 구조적으로 없애는 장치

기획서의 모든 규칙은 반드시 아래 셋 중 하나여야 합니다. 세 번째가 존재하면 파이프라인이 멈춥니다.

✓ TC가 됐다어느 TC 번호로 반영됐는지 장부에 기록됨
✓ 사유와 함께 제외됐다허용 사유 3종만: 타기획서 내용 / TC로 만들 수 없는 서술 / 중복 규칙
✕ 그냥 사라졌다허용 안 됨 → FAIL → 자동으로 TC 행 추가해 봉합
"추후구현"은 제외 사유가 될 수 없습니다. 반드시 TC로 만들고 J열에 '추후 구현'만 표시합니다. 기능이 나중에 들어와도 TC는 이미 자리를 지키고 있게.

5자주 헷갈리는 것 (오늘 대화 포함)

완료처리 문서가 왜 두 벌이야? 뭘 고쳐야 tc-team이 바뀌어?

(07-27 이사 후) 이제 답이 단순해졌습니다.

① tc-team의 모든 규칙 md는 ~\.claude\skills\tc-team\rules\ 서랍이 정본입니다. 완료처리를 바꾸려면 rules\완료처리.md 하나만 고치면 즉시 반영됩니다 (SKILL.md S7은 이 문서를 읽어 실행하라는 참조 한 줄만 남음).
② 실행 스크립트(update_dashboard.js 등 공용 설비)는 계속 scripts\util 공유 — 복사 금지.
③ v2 폴더의 문서들은 동결 원본(박제)입니다 — 고쳐도 tc-team에 반영되지 않고, rules와 내용이 달라지는 것이 정상입니다(동기화 금지).

중간에 실패하면 처음부터 다시 해야 해?

아니요. 단계마다 산출물이 파일로 남기 때문에 실패 지점부터 이어달립니다. S3는 25행 조각 단위라 어긋난 조각만 다시 하고, S5 반영 거부는 fix_plan만 다시 만들면 됩니다. 시트는 S6 전까지 무접촉이라 몇 번을 실패해도 시트는 항상 깨끗합니다.

AI가 또 숫자를 지어내면 어떡해?

지어낼 자리 자체가 없습니다. 행 번호·개수·구조는 기계가 만든 골격에 이미 있고 AI는 문장 빈칸만 받습니다. 그래도 문장 안에 이상한 표현이 섞이면 S5의 content_gate(금지표현 검사)가 기록 전에 차단합니다.

기존 v2로 만든 탭이 망가질 위험은?

없습니다. tc-team은 자기가 만든 탭에만 소유마커를 남기고, 마커 없는 탭(= v2 탭 포함 남의 탭)은 절대 삭제·덮어쓰기하지 않습니다. 이름이 겹치면 _v2, _v3… 접미사로 새 탭을 만듭니다.

이거 완전 자동이야?

정직하게 말하면 반자동 런북입니다. 버튼 하나로 끝까지 도는 게 아니라, 메인 세션(Claude)이 공정 관리자로서 S0→S7을 순서대로 실행하고 각 검문소 결과를 보며 진행합니다. 완전 무인화는 로드맵입니다.

검증은 얼마나 됐어?

자동사냥 · 주변감지 · 월드맵 3개 기능을 라이브 시트까지 완주했습니다. v2 대비 벽시계 2.2배 단축, 발명수치 0건, 원장 100% 설명(콜드런 A/B 비교, 표본 1회). 기계 부품 12종은 유닛 테스트 GREEN 상태입니다.
