- **EVAL-19 분류계층 적합성 4종**: ①대분류가 동사형(행위) 명명 ②소분류가 동작 표현이 아닌 상태 ③F열에 진입 경로가 분류와 중복 서술 ④소분류 셋업과 F열 사전상태 불일치.
- **EVAL-16 기본기능 섹션 5조건(CRITICAL)**: 최상단 배치 · 검증단계=정상/부정만 · G=PC 고정 · I=N/A 고정 · TC ID 001부터 통합 채번.
- **EVAL-14 J열 화이트리스트 정확값 5종**: 빈값 / `추후 구현` / `구현 우선순위 낮음` / `기획 확인 필요` / `DXBUG-XXXX 설명` — 이외 전부 HIGH.
- **EVAL-04 플랫폼 적정성**: 기본값 PC/모바일. PC 단독은 키보드/마우스 전용 조작에만 허용("기본적으로 PC" 축소 금지). 동일 내용의 PC/모바일 2행 분리 금지(조작 차이 서술 있을 때만 분리 — V-07d).

- **EVAL-02 검증단계 배분**: 소분류당 정상≥1·부정≥1·예외≥1 + 리스크별 부정+예외 비율 하한(HIGH≥60% / MEDIUM≥49% / LOW≥30%) — 기본기능 섹션은 집계 제외. 미달 소분류는 add 제안. **면제 인정(2026-07-28 단일화)**: 배분표 비고 `[근거부족—기획질의]` 행은 미달을 이슈로 잡지 않음 — 부족분의 "기획 확인 필요 항목" 승격 여부만 확인(미승격 시 MEDIUM, 단 토큰 뒤 `(질의 불요)` 표기 행은 승격 확인도 면제 — 구조적 사유). 이 형식 밖 자유 서술 면제는 무효. 근거 없는 상식 기반 예외 add 제안 금지(반복 호버·포커스 이탈류 — 원문 근거 필수).
- **EVAL-07 무의미 중복(논리 부정문 포함, 2026-07-28)**: ①정상을 기대결과 변화 없이 부정·예외로 복제 ②정상 문장의 **논리적 부정문** 재서술("1,000골드인지"↔"1,000골드가 아닌지")로 만든 부정·예외 — 둘 다 같은 관측 1회의 중복, delete/병합 제안. 검출 범위는 **시트 전체(대분류 경계 무관)**.
  **기계 입력**: `$WORK/dup_report.json`(dup_gate)이 있으면 Read — `exact`(F열 완전 동일)는 **기계 확정**이라 드롭 금지, delete 또는 조건 차이 명시 edit 필수(S5에서 잔존 시 체인 정지). `similar`(자카드 ≥0.85)는 후보이니 정당한 분리(BVA 상·하한, 소형/대형)인지 원문·분류로 판정. ⚠ 중복을 인지했으면 **문구를 서로 맞추는 edit 금지** — 병합하거나 차이를 드러낸다.

## [crossref] — 원문 대조 렌즈 담당

- **원문 미근거 후보(2026-07-28 신설)**: `$WORK/origin_report.json`(origin_gate)이 있으면 Read. `interaction_verb`(HIGH)=그 동작 어간이 기획서 원문에 0건 → 상식 기반 창작 후보(회고 유형 D 형상, 실측 TC321 "툴팁이 닫히는지"). `coordinate`(HIGH)=좌표 창작·행열 뒤바뀜(유형 A). `direction`(LOW)=이미지에만 있는 배치 정보 단정 의심. **후보이지 판정이 아니다** — 원문 문맥 확인 후 ①근거 없고 자명하지도 않으면 delete 또는 J='기획 확인 필요' ②원문에서 논리적으로 도출되면 유지(사유 명시). 유지도 삭제도 근거 없이 하지 말 것.
