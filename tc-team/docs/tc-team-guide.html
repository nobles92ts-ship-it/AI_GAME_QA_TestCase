1. 설계 철학 — 왜 v3인가

v2까지의 TC 파이프라인은 LLM 에이전트가 모든 것을 했다: 설계도 쓰고, 행도 만들고, 서식도 넣고, 시트에도 직접 썼다. 잘 되지만 두 가지 비용이 있었다 — ① LLM이 구조(행 순서·서식·번호)를 다루다 생기는 사고 ② 전 구간 순차 LLM 호출로 인한 시간.

v3의 답은 역할 분리다:

3원칙:

  • 구조는 코드가 소유한다 — LLM은 행을 만들지 않는다. 행 골격은 설계 문서에서 결정론 변환(convert)으로 나오고, LLM은 그 행의 문장(F열)만 채운다.
  • 신뢰하되 검증하지 않는다 — 그냥 검증한다 — LLM 출력은 echo(자기 위치 복창)·해시·전제조건 대조로 기계가 재확인한다. 판정자의 수정 지시(fix_plan)조차 "수정 전 값"이 실제 셀과 일치해야 적용된다.
  • 리뷰는 적대적으로 — 서로 다른 관점의 렌즈가 병렬로 흠을 찾고, 판정자가 상호반박시켜 실제 수정만 남긴다. 자기 출력에 자기가 관대해지는 단일 에이전트 리뷰의 함정을 구조로 막는다.

3. 파이프라인 전체 흐름 (S1~S6 + FINAL)

읽는 법: 왼쪽 세로줄이 본선(S1→S5), 게이트 다이아몬드에서 전부 PASS일 때만 시트에 닿는다. 시트가 오염될 수 있는 시점은 구조적으로 S6 단 한 곳.

4. 확대경① S3 — 병렬 문장화와 에코 게이트

왜 청크 병렬이 안전한가 — 각 에이전트는 자기 담당 행의 idx와 d(소분류)를 그대로 복창해야 한다. 한 행이라도 밀리거나(시프트) 남의 행을 건드리면 merge가 기계적으로 차단한다. 실측: 3개 기능 합계 400+행 문장화에서 시프트 0건.

자기교정 실사례 — 콜드런에서 문장화 에이전트가 원문에 없는 "500ms"를 임의로 넣었다. S4 원문대조 렌즈가 slices 원문 grep으로 적발("원문 전체에 500 계열 수치 없음"), 판정자가 제거 확정, 최종본 0건. 같은 실수를 v2는 최종본에 2건 통과시켰다 — 차이는 모델이 아니라 구조다.

6. 게이트 카탈로그 — 5계층 방어

계층구현차단/경고실측 성과
L1 입력드라이버 + design_gate.js(격리 convert)차단썩은 fetch·설계 결함 조기 정지
L2 무결성merge · apply_fix_plan.js차단문장화 400+행 시프트 0 · 패치 47건 충돌 0
L3 구조validatePreWrite · regroup.js차단그룹 분산 자동 봉합 — 단, 재배치 후 id 산술 추정 금지(§11 트러블슈팅)
L4 내용content_gate.js차단+경고 2등급신규 위임표현 규칙이 첫 가동에서 구세대 산출물의 결함 1건 적발
L5 커버리지traceability.js + 의미 매핑차단두 기능에서 기존 파이프라인도 놓친 실질 갭 3건 검출·봉합

등급 철학: 새 규칙은 경고로 태어나서 실측 후 차단으로 승격한다. 오탐으로 파이프라인을 세우는 것도 비용이기 때문.

7. 커버리지 원장 — "몇 %"가 아니라 "어느 규칙"

커버리지를 숫자 하나(%)로 말하면 두 가지 거짓말이 생긴다: 리워딩을 손실로 오판(토큰 겹침 지표의 실측 오탐)하고, 빠진 규칙이 어느 것인지 아무도 모른다. v3는 원장(ledger)으로 관리한다:

첫 가동 성과 — 원장 게이트가 기존 파이프라인(v2)도 똑같이 놓친 실질 커버리지 갭을 찾아냈다: UI 레이아웃 검증 TC 부재(기능 B), 채팅 진입 기능 무제한·거점 유일성(기능 C). 전부 TC 추가로 봉합 후 게이트 PASS. 미커버를 %에 숨기지 않고 이름으로 불러내는 것이 원장의 존재 이유다.

주의: 원장 매핑도 LLM 산출이다 — 그래서 A/B 판정 시 적대 판정자가 원장 주장 자체를 파일 대조로 재검증한다(실측에서 매퍼 오판 2건 교정됨).

8. 데이터 흐름과 파일 맵

specs/<기능명>/                ← 설계 자산 (S1, v2와 공유)
├─ confluence_raw.md           원문 스냅샷 (입력 게이트 대상)
├─ analysis.md · tc_design.md  분석·설계 (LLM, design_hash 캐싱 키)
└─ _labels.json                기획확인/테스트데이터 라벨 (FINAL-5)

<workdir>/                     ← v3 실행 작업장 (기능당 1개, 재현 가능)
├─ slices.json                 원문 조각: sections[] + rules[]   [S2]
├─ tc_skeleton.json            행 골격 (idx·분류·leaf)           [S3 convert]
├─ tc_f_map.json               F열 문장 [{idx,d,f}]              [S3 팬아웃]
├─ tc_data.json → tcteam_snapshot.json   7열 merge → 10열 스냅샷     [S3 merge]
├─ fix_plan.json (+r2…)        판정자 패치 (before/앵커 필수)    [S4]
├─ coverage.json · exclusions.json · traceability.json  원장    [S4/L5]
├─ tcteam_tc_final.json + tc_final.ok    게이트 통과 최종본          [S5]
├─ owner_marker.json           탭 소유 증명 (재기록 안전장치)     [S6]
└─ applied_patches.json        적용 이력 원장 (감사 추적)

원칙: 모든 중간 산출물이 파일로 남아 어느 단계든 재현·감사 가능. 시트에는 최종본만 닿는다.

실행 시퀀스 (콜드런)

# S1 설계 (v2 설계기 승계 — 재실행 시 해시 일치하면 스킵)
#   산출: specs/<기능>/analysis.md + tc_design.md

# S2 게이트 + 슬라이스
node tc-team/lib/design_gate.js  specs/<기능>/tc_design.md          # exit 0 필수
node tc-team/lib/slicer.js       specs/<기능>/confluence_raw.md  WORK/slices.json

# S3 골격 → 문장화(팬아웃) → merge → 스냅샷
node scripts/util/direct_convert.js convert specs/<기능>/tc_design.md WORK
#   (문장화 팬아웃: WORK/tc_skeleton.json → 25행 청크 → WORK/tc_f_map.json)
node scripts/util/direct_convert.js merge   WORK                    # 에코·해시 게이트
node tc-team/lib/snapshot_local.js WORK/tc_data.json WORK/tcteam_snapshot.json <탭명>

# S4 적대 리뷰(3렌즈+판정자) → fix_plan + 원장(coverage/exclusions)

# S5 적용 + 게이트
node tc-team/lib/apply_fix_plan.js WORK/tcteam_snapshot.json WORK/fix_plan.json WORK/tcteam_tc_final.json --ledger WORK/applied_patches.json
node tc-team/lib/regroup.js        WORK/tcteam_tc_final.json WORK/tcteam_tc_final.json
node tc-team/lib/content_gate.js   WORK/tcteam_tc_final.json              # 차단 게이트
node tc-team/lib/traceability.js   WORK/slices.json WORK/coverage.json WORK/exclusions.json WORK/traceability.json

# S6 라이브 + 완료처리 (FINAL-1·2·3·5 + 상태 원장 + read-back QA)
node tc-team/lib/sheet_write.js    WORK/tcteam_tc_final.json <시트ID> <탭명> WORK

기획 확인 루프 (미확정 스펙 처리)

  • 작성 중 미확정 발견 → 비고에 「기획 확인 필요」 플래그 (임의 확정 금지 — 위임표현은 게이트가 감시)
  • 플래그 행 + 원문 조각 자동 조인 → 기획 확인 요청서(질문·후보답변·blocking 표시) 생성 → 기획팀 전달
  • 답변 회수 → fix_plan 1패스로 해당 셀만 확정 문장 교체 + 플래그 해제 (전체 재생성 불필요)

12. 테스트 포인트 · 로드맵 · 변경 이력

테스트 포인트 (QA 확인 항목)

  • 정상: 콜드런 전 구간 완주 → 탭 행수 = 최종 스냅샷 행수(read-back 0-diff) · 원장 게이트 PASS
  • 경계: 행수가 25의 배수±1일 때 청크 경계 누락 없음 · 마지막 청크 크기 1
  • 동시성/멱등: 같은 탭 재기록 반복 → clear-and-rewrite 멱등 · 소유 마커 없는 탭은 절대 불가침
  • 실패 주입: fix_plan before 불일치 → 거부 · 앵커 유령 id → 거부 · design 변경 후 merge → 해시 FAIL
  • 권한/안전: 시트 접촉이 S6 외부에서 발생하지 않는지(감사 로그) · 격리 convert가 본 specs를 안 건드리는지

로드맵

  • 드라이버 단일 실행체 — S1~S7 원커맨드 + 착수공지·상태원장·단계별 시간 보고 내장 + 락/정지코드/재개 승계 전환 전 필수
  • 리뷰 렌즈 ↔ 기존 리뷰 규칙(EVAL 20종) 정렬 · 학습 패턴(tc-학습) 프롬프트 주입
  • FINAL-5 도출 속도 개선(현 7.1분) · 잔여 결함 fix 라운드(placeholder 갭·비확정 2·미러 중복 정책)
