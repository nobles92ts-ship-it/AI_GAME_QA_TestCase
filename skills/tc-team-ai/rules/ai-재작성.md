# AI용 TC 다시 쓰기 규칙 (tc-team-ai)

입력은 tc-team 이 기획서에서 만들고 검수까지 끝낸 TC 다. TC 한 건 = 분류 · 검증단계 · 재현 스탭 한 문장.
이 문장을 **AI 실행자가 따라 하기 쉽게 네 칸으로 나눈다.** 내용은 하나도 바꾸지 않는다 — 나누기만 한다.

| 칸 | 담는 것 |
|---|---|
| 전제 | 조작을 시작하기 전에 이미 성립해 있어야 하는 상태. 없으면 빈 배열 `[]` |
| 조작 | 실행자가 하는 행동, 하는 순서대로 |
| 기대 | 통과 조건 — 원문의 「~지 확인」 부분을 판정할 수 있는 문장으로 |
| 관측 | 무엇을 보고 판정하나 (화면 요소 · 표시 문구 · 수치) |

## 반드시 지킬 것

1. **원문에 없는 것을 더하지 않는다.** 조건·대상·수치·횟수·시간을 새로 만들지 않는다.
2. **원문의 조건을 빼지 않는다.** 원문에 있는 조건과 대상은 전부 전제나 조작에 들어가야 한다.
3. **숫자는 원문 표기 그대로.** `두 번` → `2번` 같은 바꿔 쓰기도 하지 않는다. 숫자를 새로 쓰지 않는다.
4. **기호·따옴표 문구·영문 이름은 원문 글자 그대로.** 「…」 안의 문구, `(?)` 같은 괄호 기호, `A채널`의 `A`·`HP` 같은 영문.
5. **부정은 부정으로.** 원문이 「~않는지 확인」·「~없는지 확인」이면 기대도 「~않는다」·「~없다」로 쓴다. 「~되는지 확인」이면 긍정문으로.
6. **기대가 미정이면 미정 그대로.** 원문이 「기획에서 확정한 ~와 일치하는지」처럼 기대를 정하지 않았으면 그 표현을 기대에 그대로 둔다. 그럴듯한 값을 지어내지 않는다.
7. **상태를 «어떻게» 만드는지는 쓰지 않는다.** 치트·테스트 계정·도구 이름을 지어내지 않는다. 무엇이 성립해야 하는지만 쓴다.
8. **한 항목 = 한 문장.** 머리 번호(1. · -)를 붙이지 않는다. 칸마다 1~6개(전제는 0개 가능).
9. **id 는 입력의 문자열 그대로** 돌려준다. 입력에 있는 TC 를 하나도 빼지 말고, 같은 id 를 두 번 내지 않는다.

## 예 (형식 설명용 — 실제 기능 아님)

입력:
`{"id":"021","재현스탭":"받는 사람 ID 가 빈 우편, 첨부가 0개인 유료 우편, 제목이 빈 우편을 각각 보냈을 때 매번 「발송 완료」 문구가 뜨지 않는지 확인"}`

출력:
```json
{"id":"021",
 "전제":[],
 "조작":["받는 사람 ID 가 빈 우편을 보낸다","첨부가 0개인 유료 우편을 보낸다","제목이 빈 우편을 보낸다"],
 "기대":["매번 「발송 완료」 문구가 뜨지 않는다"],
 "관측":["발송 결과 문구"]}
```

`0`·`ID`·「발송 완료」가 그대로 있고, 「않는지」가 기대의 「않는다」로 이어졌고, 원문의 우편 세 가지가 조작 셋으로 나뉘었다.
원문에 없는 전제(예: 「우편함에 빈자리가 있다」)는 그럴듯해 보여도 넣지 않았다 — 그래서 전제가 비었다.
