# 테스트 데이터 / 기획 확인 라벨링 기준 (FINAL-5 · 5a 도출용)

> 완료처리 FINAL-5의 **도출 단계(5a)**가 참조하는 판별 기준(SSoT).
> 5a가 분석·설계 산출물(+필요 시 기획서)을 읽고 이 기준으로 라벨을 도출하면,
> 5b(기재 스크립트)가 L/M에 기재한다.

---

## 0. 두 종류 정의

| 종류 | 한 줄 정의 | 받는 사람 | 시트 위치 |
|------|-----------|----------|----------|
| **기획 확인 요청** | 기획서에 안 정해졌거나·모호하거나·참조만 있어 **테스트 판정이 불가**한 것 | 기획자 | L/M **위쪽**(L 헤더 갈색) |
| **테스트 데이터 생성 요청** | 테스트하려면 **데이터에 미리 만들어져 있어야** 할 것 | 서버·기획(데이터팀) | L/M **아래쪽**(L 헤더 남색) |

> 시트 표기 순서: **기획 확인 먼저 → 테스트 데이터 나중** (확정 레이아웃).
>
> **기능 유형별 분포** (6기능 검증, 2026-06-09): 아이템/보상(소환권·패키지) = 테스트 데이터 풍부 / 스킬·UI·시스템(스나이퍼·필드보스·거점·포탈·길드) = **기획 확인 위주, 테스트 데이터 0~소수가 정상**. 데이터팀이 만들 게 없으면 비움(억지 생성 금지).

## 1. 기획 확인 요청 — 태그 4종

**주 입력 소스**: `tc_design.md`의 ① "기획 확인 필요 항목" 블록 ② **GlobalDefine 미지정(⚠)** ③ **상태전이·분류의 ⚠ 표시** ④ **신뢰 파괴 위험 요소** (+ `analysis.md` C-1/C-2).
→ ⚠ **"기획 확인 필요 항목" 섹션이 아예 없는 문서도 있음**(예: 필드보스) — 그땐 ②③④에서 수집. 절반(값 미정)은 설계가 이미 식별하므로 재활용 + 나머지(규칙 없음·모호·참조 공백) 보강.

| 태그 | 판별 기준 | V7 예 |
|------|----------|-------|
| `[값 미정]` | GlobalDefine·수치가 `N(미지정)`·`TBD` | 11회 한 번에 최대 개수 미정 |
| `[규칙 모호]` | 규칙은 있으나 해석이 갈림 | 클래스별 보상 차등 명시 없음(클래스 무관 가정) |
| `[규칙 없음]` | 동작 규칙 자체가 기획에 없음 | 보관함 만석 시 처리 미정 |
| `[참조 공백]` ⚠BLOCK | "X 참조"만 있고 구체값 없음 / **선행 시스템·외부 문서·아트 대기** 의존 → **테스트 BLOCK 직결** | 센티넬 선행 / 거점 즉시이동(외부문서 DX-254836741) / 마커 외형(아트 대기) |

**문장 형식**: `[태그] (무엇이) 정해지지 않았다 (키 괄호 병기)` + 줄바꿈 + `→ (무엇을) 판정할 수 없다`

## 2. 테스트 데이터 생성 요청 — 핵심 = "데이터 생성"

**핵심 질문**: "이 TC를 테스트하려면 **어떤 아이템·보상·표가 데이터에 만들어져 있어야** 하나?"

⚠ **범위 (가장 중요·오탐 방지)**:
- 포함 = 데이터팀이 **미리 만들어둘 것** (테스트용 아이템 자체·보상 풀 구성품·확률/등급 표·센티넬 구성품)
- **제외 = 실제 셋팅**(계정 지급·보유량 조정·만석 만들기·강제 종료 재현) — 이건 **QA 몫**

| 태그 | 의미 |
|------|------|
| `[서버·기획]` | 데이터/테이블 생성 (V7 전건이 이 태그 — **주력**) |

> ✅ **확정 (소환권 V7 + 패키지 검증)**: 테스트 데이터는 `[서버·기획]` **단일 태그**. 보조 태그(`[치트][계정·환경]` 등)는 "QA가 셋팅하는 것"이라 제외 — 데이터팀이 *데이터에 만들어둘 것*만 대상.
>
> **데이터 종류 2가지** (둘 다 요청 대상):
> 1. **정상 데이터** — 테스트용 아이템·보상 풀·확률/등급 표
> 2. **비정상·경계 데이터** — 경고/예외 검증용 (예: 아바타/탈것/센티넬 포함, 확정 100% 그룹 0개, 구성품 16개 초과)

**문장 형식**: `[서버·기획] (무엇을) 만들어주세요:` + 줄바꿈 + 각 셋업을 `• (케이스) — (값/조건) → (기대 동작)` 으로 **나열** + `▷ (목적)`

⚠ **담당자가 그 내용만 보고 그대로 세팅할 수 있을 만큼 구체적으로.** "전종류"·"여러 개" 같은 요약 금지. 조건부 생성/삭제(스폰 조건 등)는 **조건마다 동작을 명시**.

예 (포탈 스폰 조건):
```
[서버·기획] 스폰 조건별 테스트 포탈을 각 1개씩 만들어주세요:
• None — 조건 없이 항상 노출
• QuestAccepted(퀘스트 A) — A 수락 시 노출, 이후 유지
• QuestInProgress(A) — 수락 시 노출, 완료 시 삭제
• QuestNotProgress(A) — 수락 전 노출, 수락 시 삭제, 완료 후 재노출
• LevelReached(Lv10) — 레벨 10 달성 시 노출, 감소해도 유지
• RetainType=삭제 — 1회 사용 후 삭제
▷ 각 조건에서 포탈 생성/삭제/재노출이 맞는지 테스트
```

## 3. 품질 가드 4종 (필수)

1. **사람 언어** — 내부 변수명·Enum·데이터테이블명을 주어로 쓰지 않음(필요 시 괄호 병기만). [[feedback_tc_human_language_steps]]
2. **현실적인 것만** — 실제 발생 + 정말 비어서 판정 불가한 것만. 비현실 엣지(구성품 0개·등급 0개 등 "그런 경우 없는" 케이스) 제외
3. **데이터 생성만** — 실제 셋팅(QA 몫)은 제외, **데이터 생성**만 데이터팀에 요청
4. **목적 병기** — 테스트 데이터엔 `▷ 무슨 테스트인지` 한 줄 첨부
5. **셋업 구체성** — 담당자가 그 내용만 보고 **그대로 세팅 가능**하게 케이스·값·동작을 나열. 조건부 생성/삭제는 **조건마다 동작 명시**(추상적 "전종류" 금지)

---

## 4. 도출 방식

- **키워드 매칭 금지** (오탐 원인: "1회"가 "11회"에 중복 매칭, 센티넬 구성품 예시를 본품으로 오인). **맥락으로 판별.**
- 각 항목은 **근거**(어느 기획 섹션·어떤 값에서 왔는지)를 확인하고 도출. 근거 없으면 버림.
- 비어 있으면 "없음" 명시(억지 생성 금지).
- **`[추후 구현]`·취소선 항목은 라벨 대상 아님** — 미정 사양이 아니라 "나중에 만들 것"이라 J열 추후구현으로 처리(예: 패키지 '재화/경험치 미니 툴팁').

## 5. 출력 형식 (5b 전달 규약)

5a는 아래 묶음을 산출한다(중간 공유 MD 없이 5b로 직접 전달):

```
기획 확인 요청: [ {태그, 본문(\n 포함)} , ... ]   # N건
테스트 데이터 생성 요청: [ {태그, 본문(\n 포함)} , ... ]   # M건
```

→ 5b는 이를 받아 L=섹션 헤더(한 칸), M=항목 세로 나열(오버플로우, 열너비 불변)로 기재.

## 6. 예시 (소환권 V7 — 기획 문장 → 라벨)

| 기획서에 이렇게 | → 도출 | 근거 |
|------|------|------|
| 최대 개수 `Feature_MultiUseLimit` = N(미지정) | **[값 미정]** "11회 소환권 한 번에 몇 개까지 쓸 수 있는지 미정 → 다중 사용 한도 판정 불가" | C-1 |
| 센티넬은 '센티넬 관리 시스템' 참조 | **[참조 공백·BLOCK]** "센티넬 언제부터 넣을지 미정, 선행 시스템 필요" | 원문 참조 표현 |
| 만석 처리 언급 없음 | **[규칙 없음]** "보관함 만석 시 결과물 처리 미정 (TC 051)" | 규칙 부재 |
| "소환 보상 풀 = 아바타/탈것/센티넬 구성품" | **[서버·기획]** "보상 풀에 구성품 채워주세요(15개/16개+) ▷ 더보기 잘림 테스트" | 원문 |
| "확률 표기·등급 높은 순 정렬" | **[서버·기획]** "확률·등급 테이블 세팅(100%/혼합/극단값) ▷ 정렬·표기 테스트" | 원문 + B-4 경계값 |
