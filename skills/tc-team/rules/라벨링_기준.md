# 테스트 데이터 / 기획 확인 라벨링 기준 (FINAL-5 · 5a 도출용)

> 완료처리 FINAL-5의 **도출 단계(5a)**가 참조하는 판별 기준(SSoT).
> 5a가 분석·설계 산출물(+필요 시 기획서)을 읽고 이 기준으로 라벨을 도출하면,
> 5b(기재 스크립트)가 L/M에 기재한다.

---

## 0. 두 종류 정의

| 종류 | 한 줄 정의 | 받는 사람 | 시트 위치 |
|------|-----------|----------|----------|
| **기획 확인 요청** | 기획서에 안 정해졌거나·모호하거나·참조만 있어 **테스트 판정이 불가**한 것 | 기획자 | L/M **위쪽**(L 헤더 갈색) |
| **테스트 데이터 생성 요청** | 테스트하려면 **데이터에 미리 만들어져 있어야** 할 것 | 서버·기획(데이터팀) | L/M **아래쪽**(L 헤더 남색) |

> 시트 표기 순서: **기획 확인 먼저 → 테스트 데이터 나중** (확정 레이아웃).
>
> **기능 유형별 분포** (6기능 검증, 2026-06-09): 아이템/보상(소환권·패키지) = 테스트 데이터 풍부 / 스킬·UI·시스템(스나이퍼·필드보스·거점·포탈·길드) = **기획 확인 위주, 테스트 데이터 0~소수가 정상**. 데이터팀이 만들 게 없으면 비움(억지 생성 금지).

## 1. 기획 확인 요청 — 태그 4종

**주 입력 소스**: `tc_design.md`의 ① "기획 확인 필요 항목" 블록 ② **GlobalDefine 미지정(⚠)** ③ **상태전이·분류의 ⚠ 표시** ④ **신뢰 파괴 위험 요소** ⑤ **분류 그룹핑 트리 leaf 끝의 `[J:기획 확인 필요]` 태그** (+ `analysis.md` C-1/C-2).
→ ⑤는 **기획서에 기대값이 없는데 설계 방법론(8관점·상태전이·EP)에서 파생된 검증항목**이다 (`tc-설계.md` L3-7). J열만 채우고 끝내지 말 것 — **여기 L/M열에도 반드시 올린다**. 태그는 `[규칙 없음]`(동작 규칙 자체가 기획에 없음)을 쓰고, 문장에 **기획서가 정하지 않은 두 갈래를 그대로 병기**한다 (예: "재진입 시 마지막 스왑 슬롯이 유지인지 초기화인지 정해지지 않았다").
→ ⚠ **"기획 확인 필요 항목" 섹션이 아예 없는 문서도 있음**(예: 필드보스) — 그땐 ②③④에서 수집. 절반(값 미정)은 설계가 이미 식별하므로 재활용 + 나머지(규칙 없음·모호·참조 공백) 보강.

| 태그 | 판별 기준 | V7 예 |
|------|----------|-------|
| `[값 미정]` | GlobalDefine·수치가 `N(미지정)`·`TBD` | 11회 한 번에 최대 개수 미정 |
| `[규칙 모호]` | 규칙은 있으나 해석이 갈림 | 클래스별 보상 차등 명시 없음(클래스 무관 가정) |
| `[규칙 없음]` | 동작 규칙 자체가 기획에 없음 | 보관함 만석 시 처리 미정 |
| `[참조 공백]` ⚠BLOCK | "X 참조"만 있고 구체값 없음 / **선행 시스템·외부 문서·아트 대기** 의존 → **테스트 BLOCK 직결** | 센티넬 선행 / 거점 즉시이동(외부문서 DX-254836741) / 마커 외형(아트 대기) |

### 문장 형식 — **기획자에게 던지는 질문**으로 쓴다

```
[태그] (질문 한 문장 — 물음표로 끝낸다)
(왜 필요한지 한 줄 — 무엇을 어떻게 테스트하려는데 뭐가 막혔는지, 사람 말로)
```

- **1줄차 = 질문.** "정해지지 않았습니다"로 끝내지 마라 — 그건 상태 보고지 질문이 아니라서, 받는 사람이 무엇을 답해야 하는지 모른다.
- **2줄차 = 테스터 사정을 사람 말로.** `판정할 수 없음`·`검증 범위`·`경계값`·`참조 공백` 같은 QA 내부 어휘 금지(재현스탭과 같은 기준 — `tc-생성.md` 사람 언어 규칙).
- 기획서 절 번호를 쓸 거면 **기획자가 자기 문서에서 찾을 수 있는 표기**로. 우리가 수집한 조각 기준 번호는 통하지 않는다.
- **⚠ 영문 키·테이블명·컬럼명을 질문 문장에 박지 않는다 (2026-09-03 오너 지시 — 기본기능 체크리스트와 같은 기준).**
  질문은 **기획자가 쓰는 말**로 하고, 키가 필요하면 **문장 끝 괄호 각주**로 내린다. 기획자는 `DungeonResetTime`이 뭔지 몰라도 "던전이 몇 시에 초기화되는지"는 안다.
  - ❌ `[규칙 모호] 정예 던전 초기화 시각(DungeonResetTime)이 로컬 시간 기준인가요, UTC 기준인가요?`
  - ✅ `[규칙 모호] 정예 던전은 매일 몇 시에 초기화되나요? 우리 시간 기준인가요, 세계 표준시 기준인가요?` + 2줄차 끝에 `(DungeonResetTime)`
  - ❌ `[규칙 모호] EliteDungeon_UI_WeeklyReset(치환자 2개)과 EliteDungeon_UI_WeeklyResetTime(치환자 1개) 중 어느 키를 쓰나요?`
  - ✅ `[규칙 모호] 주간 초기화 안내 문구는 두 문서에 서로 다르게 적혀 있는데 어느 쪽이 맞나요?` + 2줄차에 `한쪽은 요일과 시각이 다 들어가고 다른 쪽은 시각만 들어갑니다.`
  - **예외**: 키 자체를 고르는 게 질문인 경우(둘 중 어느 키로 확정할지)는 키를 본문에 써도 된다 — 단 **무엇을 고르는 건지 한국어로 먼저** 말하고 키는 뒤에 붙인다.

**나쁜 예** (2026-08-04 실측 — 세공_시스템_개선 M25, 사용자가 "사람이 알아들을 수 없다"고 지적):
```
[참조 공백] 기획서 원문이 데이터 추가 6-1 표에서 끊겨 6-2 이후 데이터 섹션의 존재 여부가 확인되지 않았습니다
→ 추가 데이터 정의가 더 있는지 알 수 없어 데이터 기반 조건의 검증 범위를 확정할 수 없음
```
질문이 없고, 주어가 우리 쪽 사고이며, 절 번호가 우리 조각 기준이다. 기획자는 "내 문서는 멀쩡한데?" 로 끝난다.

**좋은 예**:
```
[값 미정] 세공 1회와 강화 1회에 재료가 각각 몇 개씩 필요한가요?
재료가 딱 맞게 있을 때와 1개 모자랄 때를 나눠서 확인하려는데, 필요 수량이 없어 어느 쪽이 정상인지 못 정합니다.
```

### ⛔ M열에 올리면 안 되는 것 — 우리 쪽 작업 결함

**기획자가 답할 수 없는 것은 기획 확인 요청이 아니다.** 아래는 M열이 아니라 **우리 백로그**로 간다.

| 이런 문장이 보이면 | 실제 원인 | 할 일 |
|---|---|---|
| "기획서 원문이 …에서 끊겨" | 우리 fetch 실패 | 원문 재수집 |
| "… 문서가 수집되지 않았습니다" | 우리가 그 문서를 안 읽음 | 링크 페이지 수집 |
| "… 이미지가 수집되지 않아" | 우리가 첨부를 안 받아옴 | 이미지 수집 or `/tc-이미지매칭` |
| "…xlsx …시트 …로만 기재되고 실제 값이 제시되지 않았습니다" | **우리가 테이블을 안 열어봄** | `<GAMEDATA_ROOT>\` 에서 직접 확인(xlsx 56종은 값까지 읽힌다 — 색인 `_테이블맵.md`) |

`[참조 공백]`은 **기획이 아직 못 정해서 남의 문서/선행 시스템/아트를 기다리는 상태**에만 쓴다(센티넬 선행·아트 대기처럼 **기획자가 일정을 답해줄 수 있는 것**). 우리가 안 읽은 것을 담는 통이 아니다.
실측(2026-08-04 세공_시스템_개선): M열 19건 중 **5건이 `[참조 공백]`인데 전부 우리 수집·조회 미실행**이었다.

### ⛔ 두 번째 부류 — **답이 이미 있는데 묻는 것**

앞의 표가 "우리가 안 읽어서 못 아는 것"이라면, 이쪽은 **읽었어야 할 곳에 답이 이미 있는데 질문으로 올린 것**이다.
기획자는 "그거 아까 적어놨는데"로 끝나고, 우리 질문 목록의 신뢰가 통째로 깎인다.

**올리기 전에 세 곳을 먼저 뒤진다.** 하나라도 걸리면 질문이 아니라 그 값을 TC에 쓴다.

1. **같은 기획서의 다른 절** — 특히 같은 계열의 다른 항목
2. **타 기획서 · 같은 시트의 기존 TC 탭** — 그 시스템을 이미 다룬 문서가 있으면 그쪽 소관 (`exclusions.json` 사유 `타기획서`)
3. **`<GAMEDATA_ROOT>\` 테이블** (색인 `_테이블맵.md`)

실측 (2026-08-12 인벤토리_1차_개선_v3 — 사용자가 25건 중 **7건을 "다른 내용으로 이미 알고 있는 내용"이라며 직접 삭제**):

| 지워진 질문 | 답이 어디 있었나 |
|---|---|
| 패키지·확률 상자 실패 문구·StringKey가 뭔가요 | 같은 기획서의 구매·퀘스트·업적·드랍·제작 항목이 전부 `Common_TOAST_NotEnoughInventory`로 확정 |
| 선택권 실패 문구·StringKey가 뭔가요 | 〃 |
| 빈 장착 슬롯 부위별 안내 텍스트·StringKey가 뭔가요 | 〃 (같은 계열이 이미 확정) |
| 파티 보상 분배 중 가방 가득 참 처리 | **별도 기획서 소관** (같은 시트에 `파티_보상_분배_시스템` 탭 존재) |
| 보물 상자 보상 즉시 지급 vs 우편 | 가방 Max 일반 규칙이 이미 적용 — 해당 TC들이 기대값을 확정하고 J열이 비어 있었다 |
| 탭 아이템 개수 자릿수 초과 표기 | 일반 UI 관례로 판정 가능 |
| 안내 텍스트 중 다른 슬롯 선택 시 처리 | 같은 축의 질문(재선택·재진입)이 이미 올라가 있어 중복 |

- **문자열 값(문구·StringKey)은 계열 단위로 판단한다.** 같은 계열의 다른 항목에 확정된 키가 있으면 그것을 그대로 적용하고 묻지 않는다. **계열 전체가 미정일 때만 1건으로 묶어** 묻는다 — 항목마다 쪼개 올리지 말 것.
- **같은 축의 질문은 한 건으로 묶는다.** 재선택·재진입·타슬롯 선택을 각각 올리면 기획자는 같은 답을 세 번 쓴다.

### ⛔ 세 번째 부류 — **물어봐도 테스트가 안 풀리는 것** (2026-09-03 오너 실측)

앞의 둘이 "우리가 안 읽어서"·"이미 답이 있는데"라면, 이쪽은 **답을 받아도 지금 테스트가 나아지지 않는 것**이다.
기획자의 답변 예산은 유한하다 — 목록이 길수록 진짜 물어야 할 것이 묻힌다.

**근거**: 오너가 마을_의뢰_시스템 23건 → **20건**, 정예_던전_v2 30건 → **14건**으로 직접 추렸다(총 53 → 34, **36% 삭제**). 지워진 22건은 아래 다섯 갈래로 전부 설명된다.

| 갈래 | 지워진 실례 | 왜 빼나 |
|---|---|---|
| **임시값·정식 오픈 대기** | `정식 오픈 시 기본 이용 시간은 몇 분으로 확정되나요?` · `정식 분류 이름이 무엇인가요?` | 일정이 되면 저절로 채워진다. 지금 물어도 "미정"이 답이다 |
| **리소스 경로·스트링 키 값** | `화면 배경에 들어갈 리소스 값은?` · `요구 레벨을 어떤 스트링 키로 표시하나요?` · `배경 이미지 경로를 어디서 참조하나요?` | 기획자가 아니라 아트·데이터 몫. 값이 비어도 화면 동작 검증은 된다 |
| **문서 위치 묻기** | `'남은 시간 표현 공통 규칙' 문서는 어디서 볼 수 있나요?` · `'탈출 및 귀환' 항목은 어느 문서에 있나요?` | 우리가 찾을 일이다. 정말 없으면 첫 번째 부류(수집 미실행)를 먼저 의심한다 |
| **표기·명칭 확정** | `아이템 종류 이름이 '던전 시간 충전'인가요, '던전 입장 시간'인가요?` · `챕터 숫자는 어느 컬럼 값인가요?` | 문구 한 글자 차이는 TC 문장을 못 쓰게 만들지 않는다. 실물 확인 시점에 갈린다 |
| **안 중요한 경계 수치** | `보유 상한이 있나요?` · `리스트는 몇 개부터 스크롤되나요?` · `액트는 4까지인가요 5까지인가요?` | 그 값을 몰라도 정상 경로 TC가 그대로 성립한다 |

**남긴 것의 공통점 — 「몰라서 테스트를 못 짜는 것」.** 실제로 살아남은 34건은 대부분 **동작 규칙**이었다
(정예 잔존 14건 중 **9건이 `[규칙 없음]`** — 재잠금 시 동작·최초 진입 기본값·탭 이동 후 선택 유지·던전 안에서 초기화 시각을 넘겼을 때).
마을도 초기화 시각·횟수 상한·비용처럼 **그 값이 없으면 판정 자체가 불가능한 것**만 남았다.

**판별식 한 줄**: *이 답을 못 받으면 지금 TC를 못 쓰는가?* — **아니오면 올리지 않는다.**
답이 없어도 정상 경로 TC가 써지면, 그건 질문이 아니라 나중에 확인할 메모다.

⚠ 이 절은 **기계가 잡지 않는다**(무엇이 "안 중요한지"는 정규식으로 안 갈린다). 5a 도출 단계에서 스스로 거른다.

### 수치를 물을 땐 **후보값을 함께 낸다**

`[값 미정]` 질문은 열린 질문으로 끝내지 말고 **우리가 짐작한 값을 붙여** 기획자가 O/X로 답할 수 있게 한다.
근거는 실측 — 위 런에서 사용자가 남긴 두 건에 직접 후보값을 덧붙였다.

```
[값 미정] 인벤토리 슬롯 최대 개수가 몇 개인가요? 500개 인가요?
[값 미정] 1슬롯에 스택 가능한 아이템을 최대 몇 개까지 쌓을 수 있나요? 9999개로 통일인지 아이템마다 다른가요?
```

후보값은 테이블·유사 시스템·기존 TC에서 끌어오고, 짐작이면 그렇게 보이게 쓴다(단정 금지).

## 2. 테스트 데이터 생성 요청 — 핵심 = "데이터 생성"

**핵심 질문**: "이 TC를 테스트하려면 **어떤 아이템·보상·표가 데이터에 만들어져 있어야** 하나?"

⚠ **범위 (가장 중요·오탐 방지)**:
- 포함 = 데이터팀이 **미리 만들어둘 것** (테스트용 아이템 자체·보상 풀 구성품·확률/등급 표·센티넬 구성품)
- **제외 = 실제 셋팅**(계정 지급·보유량 조정·만석 만들기·강제 종료 재현) — 이건 **QA 몫**

| 태그 | 의미 |
|------|------|
| `[서버·기획]` | 데이터/테이블 생성 (V7 전건이 이 태그 — **주력**) |

> ✅ **확정 (소환권 V7 + 패키지 검증)**: 테스트 데이터는 `[서버·기획]` **단일 태그**. 보조 태그(`[치트][계정·환경]` 등)는 "QA가 셋팅하는 것"이라 제외 — 데이터팀이 *데이터에 만들어둘 것*만 대상.
>
> **데이터 종류 2가지** (둘 다 요청 대상):
> 1. **정상 데이터** — 테스트용 아이템·보상 풀·확률/등급 표
> 2. **비정상·경계 데이터** — 경고/예외 검증용 (예: 아바타/탈것/센티넬 포함, 확정 100% 그룹 0개, 구성품 16개 초과)

**문장 형식**: `[서버·기획] (무엇을) 만들어주세요:` + 줄바꿈 + 각 셋업을 `• (케이스) — (값/조건) → (기대 동작)` 으로 **나열** + `▷ (목적)`

⚠ **담당자가 그 내용만 보고 그대로 세팅할 수 있을 만큼 구체적으로.** "전종류"·"여러 개" 같은 요약 금지. 조건부 생성/삭제(스폰 조건 등)는 **조건마다 동작을 명시**.

예 (포탈 스폰 조건):
```
[서버·기획] 스폰 조건별 테스트 포탈을 각 1개씩 만들어주세요:
• None — 조건 없이 항상 노출
• QuestAccepted(퀘스트 A) — A 수락 시 노출, 이후 유지
• QuestInProgress(A) — 수락 시 노출, 완료 시 삭제
• QuestNotProgress(A) — 수락 전 노출, 수락 시 삭제, 완료 후 재노출
• LevelReached(Lv10) — 레벨 10 달성 시 노출, 감소해도 유지
• RetainType=삭제 — 1회 사용 후 삭제
▷ 각 조건에서 포탈 생성/삭제/재노출이 맞는지 테스트
```

## 3. 품질 가드 4종 (필수)

1. **사람 언어** — 내부 변수명·Enum·데이터테이블명을 주어로 쓰지 않음(필요 시 괄호 병기만). [[feedback_tc_human_language_steps]]
2. **현실적인 것만** — 실제 발생 + 정말 비어서 판정 불가한 것만. 비현실 엣지(구성품 0개·등급 0개 등 "그런 경우 없는" 케이스) 제외
3. **데이터 생성만** — 실제 셋팅(QA 몫)은 제외, **데이터 생성**만 데이터팀에 요청
4. **목적 병기** — 테스트 데이터엔 `▷ 무슨 테스트인지` 한 줄 첨부
5. **셋업 구체성** — 담당자가 그 내용만 보고 **그대로 세팅 가능**하게 케이스·값·동작을 나열. 조건부 생성/삭제는 **조건마다 동작 명시**(추상적 "전종류" 금지)

---

## 4. 도출 방식

- **키워드 매칭 금지** (오탐 원인: "1회"가 "11회"에 중복 매칭, 센티넬 구성품 예시를 본품으로 오인). **맥락으로 판별.**
- 각 항목은 **근거**(어느 기획 섹션·어떤 값에서 왔는지)를 확인하고 도출. 근거 없으면 버림.
- 비어 있으면 "없음" 명시(억지 생성 금지).
- **`[추후 구현]`·취소선 항목은 라벨 대상 아님** — 미정 사양이 아니라 "나중에 만들 것"이라 J열 추후구현으로 처리(예: 패키지 '재화/경험치 미니 툴팁').

## 5. 출력 형식 (5b 전달 규약)

5a는 아래 묶음을 산출한다(중간 공유 MD 없이 5b로 직접 전달):

```
기획 확인 요청: [ {태그, 본문(\n 포함)} , ... ]   # N건
테스트 데이터 생성 요청: [ {태그, 본문(\n 포함)} , ... ]   # M건
```

→ 5b는 이를 받아 L=섹션 헤더(한 칸), M=항목 세로 나열(오버플로우, 열너비 불변)로 기재.
