# § 1. 실행 가이드 (HOW)

## 1.0 가용성 게이트 (배포 안전 — CRITICAL)
- **tc-대조는 필수 단계가 아니라 선택 플러그인이다.** 파이프라인은 대조 없이도 유효한 TC를 낸다(현행 동작).
- 이 파이프라인은 GitHub로 공개·공유된다. **기본 가정 = 받는 사람은 '뇌'가 없다.** 그 환경에선 대조 + 기획서 탐색·질의까지 **통째로 건너뛴다.**
- **모드는 `off` / `on` 둘뿐** (auto·런타임 프로브 없음):
  - **`off` (배포 기본값)**: 대조 통째 스킵. `dxr_crossref.json` 미생성. 분석→설계 직행(현행 동일). **기획서 탐색·뇌 질의 일체 안 함.**
  - **`on` (브레인 보유자 로컬 설정)**: 대조 실행. **단 fail-safe** — 별도 프로브 없이 그냥 뇌에 질의를 시도하고, 어떤 런에서 안 닿으면(context-mode 미탑재·색인 없음·에러) **로그만 남기고 스킵(파이프라인 중단 금지)**. 평소엔 항상 실행, 사고 나도 TC는 계속.
- **1회 셋업** (설치 시 config 없을 때만 — 매 런 묻지 않음):
  - 질문: *"기획서를 분석·연결·색인해둔 '뇌'가 있나요?"* (뇌가 뭔지 = 셋업 가이드 참조)
  - **없다 → `off`** (영구 스킵).
  - **있다 → `on`** → 셋업이 그 뇌(색인 `source` / manifest 경로)를 **찾아 보여주고 사용자가 확인** → 확정값을 머신-로컬 config에 저장.
  - config 있으면 다시 묻지 않는다.
- **경로는 대조 config에 두지 않는다**: 실제 기획서 경로는 각자의 **뇌 manifest(roots)** 가 보유. 대조 config = **모드(off/on) + 색인 source 이름**만.
- **머신-로컬·미커밋**: config는 공개 레포에 커밋 금지(gitignore). 레포엔 **기본값 `off` + 셋업 가이드**만 동봉. 가이드는 *"뇌가 뭔지 + off/on 설명"*만 — **뇌 만드는 법은 적지 않는다**(목적 외).
- **배포 위생**: 공개 레포엔 **이 스킬(규칙)만** 올리고 **뇌 코퍼스(DXR 원문)는 올리지 않는다.** 데이터 없이도 스킬은 무해(게이트가 자동 비활성).

## 1.1 역할
- **입력**: `analysis.md`의 **C-1 미지정 목록** + **B-2 외부 의존성 표** (analysis.md를 직접 파싱 — candidates.json엔 C-1/B-2가 직렬화되지 않으니 입력원으로 쓰지 말 것). `tc_design.md` "기획 확인 필요 항목"(C-1의 설계 승급본)도 동일 내용 — 어느 쪽을 읽어도 무방, 중복 카운트 금지.
- **처리**: 각 항목을 뇌(`ctx_search`, `source`=config.crossref_source 기본 `"brain-corpus"`)에 대조 → §1.3 4분기 결정트리.
- **출력**: `dxr_crossref.json` (설계가 소비 — 배선은 후속, §3 참조).
- ⚠ **분석/설계 컨텍스트를 늘리지 않기 위해 자체 호출(별도 컨텍스트)로 돈다.** 입력은 위 두 표만, 규칙은 이 파일만, 결과는 작은 JSON으로만 넘긴다. (STEP1 비대화 → 누락 방지)

## 1.2 핵심 원칙 (CRITICAL — TC 추론 금지 원칙의 적용)
1. **브레인은 발명하지 않는다.** 위치·근거(출처 페이지)만 댄다. 뇌가 반환한 내용을 넘어 추론으로 값을 지어내지 않는다. (TC 핵심 = 기획서에 없는 내용 임의 추론 금지)
2. **로컬 데이터 테이블 값은 가져오지 않는다.** `TargetRange` 실제 수치처럼 **로컬 PC 설치 테이블**에 있는 값은 **위치만 안내**하고, 값 입력은 사람 몫(②로 분기).
3. **의심스러우면 전환하지 않는다.** 틀린 전환 1건이 헛 기획확인 10건보다 나쁘다. 확신 없으면 ④(유지).

## 1.3 4분기 결정트리 (항목마다)
각 항목 → 뇌 질의 → 정확히 하나로 분류:

| 분기 | 조건 | 처리 | 라벨 |
|---|---|---|---|
| **① 적용** | 위키에 **완전한 정의·규칙(값까지)** 있음 | TC에 적용할 확정 스펙 + 출처 | `apply` |
| **② 위치기록** | 정의 **위치는 알지만 값이 로컬 테이블/외부** | 기획확인 요청에 "여기 보면 됨" + 출처 첨부 (사람 확인) | `locate` |
| **③ 발굴** | 능동 탐색으로 **누락 교차규칙** 발견(불확실) | 설계 커버리지에 TC 후보 + 기획확인 요청(후처리용) | `discover` |
| **④ 유지** | 가드 걸림 또는 근거 없음 | 전환 없이 기획확인 그대로 유지 | `keep` |

> 갈림길 결정 반영(2026-06-18): ㉠=사람 승인(자동 적용 금지, 외부값은 ②로 기록) · ㉡=능동 탐색 ON(③) · ㉢=가드 전부 ON(§1.4).

## 1.4 가드 (전부 ON — 위반 시 ④로 보냄)
- **스텁 페이지**: 본문이 비어있으면(예: `[시스템/몬스터] AI` 스텁) 전환 금지. 역참조 힌트만 남김(예: "보스 방향성 페이지 참조").
- **`(작성중)`·`(작성_중)`·`(홀드)` 페이지**: 미완 기획값을 확정 스펙으로 쓰지 않는다.
- **애매한 매칭**: 출처가 불분명하거나 확신 낮으면 전환 금지.
- **출처 필수**: ①②③ 모든 전환·기록에는 **출처 페이지(+섹션)를 반드시** 단다. 출처 없으면 전환 무효 → ④.

## 1.5 뇌 질의 프로토콜
- 도구: `ctx_search(queries=[...], source=<config.crossref_source>)`. **source 는 `team/tc_config.json` 의 `crossref_source`(기본 `"brain-corpus"`) 를 읽어 사용** — 하드코딩 금지(2026-07-11 적대리뷰 #24: 각자 뇌면 자기 색인 이름). 항목들을 모아 **한 번에 배치 질의**(라운드 최소화).
- 질의어: 항목의 키/용어 2~4개 (예: `"TargetRange 사거리 표기 규칙"`, `"어그로 전이 규칙"`, `"전투상태 진입 조건"`).
- **계층 가드 (CRITICAL — 2026-07-11 적대리뷰 #10)**: `ctx_search` 결과 각 청크의 헤더 `### [계층/도메인] 경로` 를 반드시 확인한다. **근거로 채택(apply/locate/discover의 source)할 수 있는 것은 `[D/DXR]` 헤더 청크뿐.** `[R]`(과거 TC 산출물 specs·tc_design), `[P]`(스킬·개인메모리), `[E]`(리뷰·피드백) 청크는 **위키 정의가 아니므로 근거 금지** — 이것들만 걸리면 그 항목은 `keep`. (순환 인용: 과거 tc_design 을 위키 정의로 오인해 TC가 과거 TC를 근거로 재생산하는 것을 차단. note 에 채택 청크의 헤더 경로를 남긴다.)
- **테이블맵 직접 대조 (locate 전용 — 2026-07-11 적대리뷰 #11, FTS 의존 끊기)**: `locate`(② 로컬 테이블 값) 후보는 FTS 랭킹에 밀려 위치를 못 찾는 경우가 많다. 판정 전 항목의 **테이블/컬럼명으로 `Grep`** 을 `{WORK_ROOT}\DXR_관리\_DXR_테이블맵.md` 에 직접 돌려(예: `Grep pattern="StatusGroup" path=_DXR_테이블맵.md`), 적중하면 note 에 **xlsx 파일·시트·컬럼·조인율**을 기재하고 "값은 원본 xlsx 에서 확인(SynapseMap 수치와 트렁크 스냅샷 차이 가능)" 경고를 붙인다. 테이블맵 미존재/무적중이면 종전대로 위키 위치만 안내.
- 1홉 한계: `ctx_search`는 매칭 페이지만 반환(자동 그래프 전개 없음). 역참조/유사 시스템이 결과에 보이면 **필요한 것만 1홉 후속 질의**.
- **능동 탐색(③)**: 마지막에 1회 — `"이 기능 유형(보스/몬스터)에 보통 적용되는 DXR 공통 규칙 중 대상 페이지에 빠진 것?"`. 결과는 **후보일 뿐, 사실 단정 금지** → 전부 ③(기획확인+후보)로만. (여기서도 계층 가드 적용 — `[D/DXR]` 근거만.)

## 1.6 무적중·빈 입력 처리 (비파괴 원칙 — CRITICAL)
- **대조는 절대 상황을 악화시키지 않는다 (monotonic).** 못 찾으면 현행과 동일, 찾으면 딱 그만큼만 이득.
- 한 항목이 뇌에서 **아무것도 안 끌리면** → **④ keep** (전환 0, TC 영향 0). 기존 기획확인 그대로 설계로.
- **새로 시작하는 콘텐츠**(DXR에 선례 없음)라 대조 대상이 통째로 없으면 → 전 항목 `keep`, `counts.keep == in`. 설계는 현행과 100% 동일하게 진행.
- **C-1 미지정 + B-2가 둘 다 비면** 대조 자체를 스킵(early exit)하고 빈 `dxr_crossref.json`(`counts.in=0`)만 남긴 뒤 설계로 넘긴다.
- 뇌·색인 장애(검색 불가)도 동일 처리: **전 항목 keep + 스킵 사유 로그** → 파이프라인 막지 않음.

# § 2. 출력 스펙 (WHAT)

## 2.1 dxr_crossref.json (강제 구조)
```json
{
  "source_run": "<기능명/런 식별>",
  "items": [
    {
      "id": "C1-3",
      "term": "TargetRange",
      "branch": "locate",
      "source": "사거리_표기_규칙",
      "note": "정의=시전 최대거리(m). 실제 값은 로컬 [스킬테이블] 확인 요망",
      "approved": false
    }
  ],
  "discovered": [
    {
      "rule": "자동사냥 on/off 적용 여부",
      "source": "자동사냥_시스템",
      "confidence": "low",
      "as": "기획확인+TC후보"
    }
  ],
  "counts": { "in": 12, "apply": 0, "locate": 0, "discover": 0, "keep": 0 }
}
```
- **`apply`라도 값이 외부면 `approved:false`**로 두고 사람 승인 대기(→ 기획확인 요청 기록). 위키에 값까지 완전할 때만 `approved` 후보.
- **`source` 비면 그 항목은 무효** — `keep`으로 강등(가드 §1.4).
- **`counts`로 효과 측정**: 들어간 N → 분기별 수. count_gate 식 게이트·A/B(대조 on/off) 비교의 근거.

## 2.2 자체 검증 체크리스트
```
[ ] 모든 item에 branch ∈ {apply, locate, discover, keep}
[ ] apply/locate/discover 전부 source 있음 (없으면 keep)
[ ] 스텁·(작성중)·(홀드)·애매 → keep (전환 0건)
[ ] 로컬 테이블 값 = locate (값을 지어내 apply한 것 0건)
[ ] counts.in == items 길이, 분기 합 == in
```

# § 3. 설계 연결 계약
> ⚠ **배선(2026-06-19 결정론화)**: 대조는 STEP2 직전 **run_pipeline.sh가 전용 `tc-대조-v2` 에이전트를 bash로 결정론 호출**해 `dxr_crossref.json` 생성(`crossref_brain=on`일 때). 검수(STEP2)·수정(STEP3)이 이 JSON을 **직접 소비**. 검수 에이전트 self-gate(LLM 자율 실행) 방식은 **폐기** — 검수원이 대조를 자율 스킵해 미발화하던 버그 픽스(v4·v5 실측). `tc-설계.md` 본문(L372/L541) 직접 편집은 미배선 → STEP3가 `dxr_crossref.json` 기반 **best-effort 적용**(analysis.md/tc_design.md 외과 수정). 아래는 소비 계약.
- `apply` (**`approved:true`만** — 위키에 값까지 완전) → 설계 **커버리지 매핑표**에 확정 규칙(+출처). STEP3(needs_fix 트리거)가 소비. **`approved:false`(값이 외부/로컬 테이블)는 확정 금지 → `locate`와 동일 처리**.
  - **신뢰 앵커 게이트 (2026-07-12 적대리뷰 #14)**: vault 는 무인 Sonnet 머지 산출물이라 오염 가능 → `apply(approved:true)` 항목은 **반드시 `page_id`(+가능하면 원본 URL)를 수록**해 추적성을 남긴다. 근거 청크에 `<!-- REVIEW: 원문 미확인 주장 -->` 마커(weekly STEP 3.5.1)가 있으면 apply 금지 → `locate` 강등(사람 확인). apply 는 실측상 극소수(전 런 통산 ~1건)라 이 게이트 비용은 무시 가능.
- `locate` / `apply(approved:false)` → 설계 **"기획 확인 필요 항목 (DXR 대조)"** 블록에 출처/위치 첨부("여기 보면 됨"). **배선(2026-07-12 적대리뷰 #9)**: 이 둘은 needs_fix 트리거가 아니므로 STEP3가 안 돌 수 있다 → run_pipeline.sh가 **STEP4 직전에 `crossref_annotate.js`(결정론·멱등)로 `dxr_crossref.json`에서 직접 tc_design.md에 주입**한다. STEP3의 LLM 소비에 의존하지 않음(locate-only 런에서도 반드시 설계·시트에 반영). "STEP4가 흡수한다"는 옛 문구는 폐기 — 흡수기가 명시적 스크립트로 존재.
- `keep`    → 전환 없음. 기존 기획확인 그대로(대조가 아무것도 추가/삭제 안 함).
- `discover`→ 설계 **커버리지 매핑표**에 TC 후보 + 기획확인. STEP3(needs_fix 트리거)가 소비.
