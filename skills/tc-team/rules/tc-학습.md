# TC 학습 — 활성 큐 (스킬 미반영 보완 패턴)

> **목적**: 스킬에 아직 정식 반영 안 됐거나, 반영됐어도 재발 중인 패턴만 모은 "보완 큐". 매번 읽기 대상이라 **가볍게 유지**한다.
> **읽는 주체**: tc-설계검수(STEP 2), tc-리뷰1수정1(STEP 5)
> **읽지 않는 주체**: tc-designer(STEP 1), tc-writer(STEP 4), tc-리뷰2수정2(STEP 6)
> **분리 파일** (매번 읽지 않음): 1회 발견 누적 → `tc-학습-관찰.md` / 적용완료·갱신이력 → `tc-학습-이력.md`
> 모든 내용은 한국어.

## 보강 사이클 (운영 규칙)
1. **축적**: 회귀/리뷰 1회 발견 → `tc-학습-관찰.md`에 1행 append
2. **승격**: 같은 유형 **2회+ 재발** → 이 파일(활성)에 패턴 등록  ※ `/tc-학습-수집`의 QA 실측 발견은 고신뢰 → **활성 직행**
3. **승화**: 3달마다 활성 패턴을 해당 스킬에 정식 반영 → 활성에서 제거 + `tc-학습-이력.md`에 기록
4. **재발감시**: 스킬 반영했는데 또 터지면 → 활성에 `재발감시`로 복귀 (규칙 강화 / 기계검증 격상 후보)

- **증상**: 기획서가 열거값(탭 종류·아이템 타입·부위·등급·보상 종류)을 명시했는데 TC는 "각 ~별로 표시되는지" 1건으로 묶음. P-20(BVA 상·하한 통합)의 열거값 버전 — 실제로는 값별 데이터 연결이 달라 개별 검증이 필요한데 1건이 통과하면 전체가 통과한 것처럼 보임.
- **검수**: 기획서에 열거값 목록이 표·불릿으로 제시된 항목은 값 수만큼 TC가 있는지. 트리·배분표 문구에 "각 ~별", "~마다", "~별로" 패턴이 있는데 대응 TC가 1건이면 값 단위 분리 지시.

### P-21: dup_event(중복 차단)를 refresh(지속시간 갱신)로 오인 누락  `재발감시` 재발 1회
- **발견**: Boss_0011 v6 (2026-06-13) — 전개기 게이트가 점프공격·물방울의 dup_event(동일 이벤트 재발생 시 비정상 전이 차단)를 gap으로 적발했으나, STEP 2 리뷰어가 "재피격/재적중 시 지속시간 갱신(정상)" 케이스를 근거로 둘 다 오기각(독립 반박검증 7건 중 2건 real_gap). v5 넉다운에서도 같은 혼동.
- **증상**: 상태/지속효과(기절·넉다운·이속감소·연출)를 부여하는 소분류에 **중복 차단** 케이스가 없고 **갱신(refresh)** 케이스만 존재 — 둘은 정반대 의도(부정 vs 정상)인데 갱신을 중복차단 커버로 간주. 같은 기능군 다른 소분류(부위파괴·그로기·뒤집힘)는 dup_event를 뒀는데 일부만 빠짐 = 내부 불일치.
- **설계(shift-left)**: 상태/연출을 부여하거나 재생하는 **모든** 소분류에 dup_event(중복 트리거 차단/재발동 방지/무한 루프 차단)를 refresh와 **별도 케이스**로 둔다. 한 소분류라도 빠지면 누락.
- **검수**: 게이트 dup_event gap을 "갱신 케이스 있음"으로 기각 금지 — 실제 "중복 차단" 케이스 존재 또는 기획상 중복 불가능 명시일 때만 ⊘. (tc-설계검수.md C-12 게이트 소비 규칙과 동일)
- **재발**: Boss_0006_괴조_보스_v2 (2026-06-17) — 오염 장판 소분류에 dup_event(뼈 토하기 재시전 시 중복 장판 트리거 차단) 누락. refresh(반복 체류 누적, 예외-1) 케이스는 있으나 dup_event는 설계·TC 모두 없음. 1차 리뷰 EVAL-12에서 검출 후 신규 예외 TC 추가로 수정.
