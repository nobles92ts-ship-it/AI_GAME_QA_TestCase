## 실행 순서 · 정책

- 순서: **FINAL-0 → 1 → 2 → 5 → 3** (+ 6 안내). 확신도(0)가 맨 앞 — 스탬핑 요약이 완료 보고에 실리기 위함. 라벨링(5)이 드라이브 업로드(3)보다 먼저 — `_labels.json`까지 드라이브에 포함시키기 위함.
  <!-- 위 굵은 순서 문자열을 finalize.sh가 파싱한다. 단계 번호를 바꾸면 실행 순서가 바뀐다. 지원 단계=0·1·2·3·5 -->
- 실행기: `bash tc-team/scripts/finalize.sh --feature <기능명> --sheet-id <ID> --tab <실제탭명> [--conf-url <URL>]`
  — 데스크톱·Loki 공용. 아래 FINAL-N 절의 명령 블록은 **그 스크립트가 무엇을 하는지 적은 설명**이며,
  명령을 손으로 따라 칠 필요는 없다.
- **단발 재실행**: `--only <단계>` (쉼표·공백 구분, 지원 0·1·2·3·5). 예 — 인증 만료로 라벨링만 다시:
  `bash finalize.sh --feature <기능명> --sheet-id <ID> --tab <탭명> --only 5` / 패널만 다시: `--only 2`.
  이때는 위 순서를 무시하고 지정 단계만 돈다.
- 실패 정책: 한 단계 실패해도 **다음 단계 계속**(try/continue). 보고에 ✗+사유 기재. 재시도는 단계당 최대 1회.
- v2의 FINAL-4(리포트 수치 재덤프 검증)는 tc-team에선 **S6 read-back(0-diff)으로 갈음** — §FINAL-4 참조.

## FINAL-5: 기획 확인 라벨링 (L/M열, 12행~)

> ⚠ **테스트 데이터 라벨링은 여기서 실행하지 않는다** — 이미지 매칭과 동일하게 선택·수동(추후 셋팅, 2026-07-27 사용자 확정). FINAL-6에서 안내만.

**5a. 도출 (agent — 팀장이 위임 호출)** — 별도 컨텍스트의 agent에게 아래 1~3 지시 (구 인라인 S7 승계, 실측 7.1분):
1. `$SPEC/analysis.md`(C-1 미지정값·C-2 모호) + `tc_design.md`(기획 확인 필요 항목) 읽기
2. 같은 폴더 `라벨링_기준.md` 기준으로 **기획 확인(태그 4종)만** 도출 — 품질 가드 4종 적용, 근거 확인, 키워드 매칭 금지
3. `$SPEC/_labels.json` 저장:
   ```json
   { "기획확인": ["[값 미정] 본문\n→ 판정 불가...", ...] }
   ```
   `테스트데이터` 키 생략 — `apply_labeling.js`가 `|| []` 처리해 기재 자동 스킵.

⚠ **산출 직후 `JSON.parse` 검증 필수** — `$UTIL/validate_labels.js`를 finalize.sh가 5b 앞에서 자동 호출한다.
- **본문에 기획서 문구를 인용할 때 `"`를 반드시 `\"`로 이스케이프**한다. 한 곳만 빠져도 파일 전체가 무효 JSON이 되어 기획 확인 요청이 **통째로** 유실된다.
  - 실사고(2026-08-07 기능B_v3): 이스케이프 1곳 누락 → 9건 전원 미기재. try/continue라 런은 초록불로 완주했고 사흘 뒤 사람이 시트를 열어보고서야 발견.
  - 깨진 예 `이 20종이 "테이블에 없고 미구현"이라고` / 바른 예 `이 20종이 \"테이블에 없고 미구현\"이라고`
- 검증기는 파싱 실패 시 이스케이프 교정을 **1회만** 시도한다(성공 시 깨진 원본을 `_labels.broken.json`으로 보존). 그래도 실패하면 **실패 배너**를 `$SPEC/.final5_alert.txt`에 남긴다 — 경고 한 줄로 흘리지 않는다.
- 파싱 성공 시에도 규격을 검사해 위반 **건수를 chain.log에 남긴다**: 태그가 4종(`[값 미정]`·`[규칙 모호]`·`[규칙 없음]`·`[참조 공백]`) 중 하나로 시작하는지 · 각 항목에 `\n→` 근거가 있는지. (위반은 기록만 — 기재를 막지 않는다)

## FINAL-3: 드라이브 업로드 — 신규 파일만

```bash
"$NODE" "$UTIL/upload_md_to_drive.js" --folder "$FEATURE_NAME" <드라이브에 처음 올라가는 신규 파일만>
```

- ⚠ **동명 파일 처리는 `--folder`·`--sync` 공통**: 드라이브에 같은 이름이 있으면 덮어쓰기가 아니라 `이름_YYYYMMDD(_vN)` 타임스탬프 사본이 새로 생성됨(스크립트에 update 경로 없음). 두 모드의 차이는 대상 범위뿐(--sync=specs 전체 / --folder=지정 파일).
- 따라서 대상은 **드라이브에 처음 올라가는 신규 파일만** (예: 첫 런의 analysis·tc_design·_labels). 이미 올라간 파일의 갱신본 재업로드 금지 — 갱신 반영이 꼭 필요하면 드라이브 기존 파일 삭제 후 업로드.
- **`--sync`(specs 폴더 전체) 금지** — 기존 파일 전부가 사본으로 중복 생성됨.
- 드라이브 API 쿼터 오류 → 60초 대기 후 1회 재시도.
