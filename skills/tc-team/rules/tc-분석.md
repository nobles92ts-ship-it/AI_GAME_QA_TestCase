# § 1. 실행 가이드 (HOW)

## 1.1 역할

기획서를 분석하여 **`analysis.md`** 생성.

> **파일명 규약 (엄수)**:
> - **로컬 specs 파일명**: `analysis.md` / `tc_design.md` — 파이프라인·에이전트 참조용
> - **드라이브 업로드 파일명**: `DX-[기능명]_분석_text_1.md` / `DX-[기능명]_tc_design.md` — 사람 구분용
> - 본 문서에서 "analysis.md" = 로컬명, "분석_text_1.md" = 드라이브 별칭. 혼용 금지.

1. 기획서 내용 가져오기 (입력 유형별 처리)
2. 원문 마크다운 정리 → `analysis.md` 작성 (드라이브 별칭: `DX-[기능명]_분석_text_1.md`)
3. 테스트 관점 분석 (EP, BVA, 상태 전이, 결정 테이블) 수행
4. 분석 결과 tc-설계 단계 전달 가능 상태로 저장

## 1.3 입력 유형 감지 및 처리

> ⚠️ **파이프라인 모드 우선 규칙**: 핸드오프에 `confluence_raw.md` 파일 경로가 포함되어 있으면, Confluence URL이 있더라도 **절대 `getConfluencePage`를 호출하지 않는다.** `confluence_raw.md`를 Read 도구로 읽어 그것을 기획서 원문으로 사용한다. 팀장(tc-팀-v2)이 이미 저장해둔 파일이다.

| 입력 유형        | 판별 기준                                | 처리 방식                           |
| ---------------- | ---------------------------------------- | ----------------------------------- |
| 파이프라인 파일  | 핸드오프에 `confluence_raw.md` 경로 포함 | Read 도구로 파일 직접 읽기 (최우선) |
| Confluence       | URL에 `atlassian.net` 또는 `/wiki/` 포함 | Atlassian MCP (`getConfluencePage`) |
| PDF              | `.pdf` 확장자 또는 경로                  | `Read` 도구로 직접 읽기             |
| Word (doc/docx)  | `.doc` / `.docx` 확장자                  | `Read` 도구로 직접 읽기             |
| Excel (xlsx/xls) | `.xlsx` / `.xls` 확장자                  | Bash + Node.js로 파싱               |

> 🎯 **QA 스코프 지시서 (조건부)**: `$SPEC/qa_scope.md` 가 있으면 **기획서를 읽기 전에 먼저 읽는다.** QA 리드가 정한 이번 TC의 검증 범위이고, 범위 밖으로 지정된 항목은 분석 후보에서 뺀다(§3.9). **이 파일은 기획서가 아니다** — 여기 있는 내용을 원문 근거로 인용하지 말 것. 없으면 무시(기본값).

> 🔗 **링크 선수집분 (Confluence)**: `$SPEC/linked/` 가 있으면 S0이 본문 링크를 1홉 선수집해둔 것이다. **미지정·모호 항목을 기획 확인으로 올리기 전에 여기부터 확인** — 사용 규칙은 §3.8. 폴더가 없으면 무시(링크 없는 기획서·공개 배포).

> 📎 **첨부파일 목록화 의무 (Confluence)**: Confluence 페이지에 첨부(xlsx/pdf 등)가 존재하면 **파일명 전수**를 analysis.md에 목록화한다. 내용 미수집 시 각 항목에 `[ATTACHMENT: <파일명>, 미수집]` 명시 — 조용한 공백 금지. 첨부에만 존재하는 수치·표는 **외부 의존**으로 B-2 표에 기록(유형=`첨부`, 등장 섹션=해당 첨부 파일명).

### Confluence 처리 (confluence_raw.md 없을 때만)

- Atlassian MCP(`getConfluencePage`)로 **ADF 형식**으로 가져오기
  - cloudId: `your-site.atlassian.net`
  - pageId: URL 마지막 숫자
- **취소선(`strike` mark) 포함 모든 서식 누락 없이 확인**
  - 취소선 텍스트는 반드시 `~~텍스트~~` 형식으로 변환
  - 링크, 볼드, 이탤릭 등 서식도 그대로 반영
- **expand(접힌 블록) 내부 텍스트는 본문과 동급으로 전부 포함** — 접혀 있다는 이유로 생략 금지
- **참조형 매크로(include·excerpt(타 페이지 삽입)·Jira 이슈 매크로·page-properties 등)는 내용이 응답 본문에 오지 않으므로**, 해당 위치에 `[MACRO: <종류> → <대상 페이지/이슈>, 미수집]` 표기 의무 — 조용한 공백 금지
- **표의 병합 셀은 구조(어느 셀이 병합인지)를 잃지 않게 변환** — 병합 범위를 명시하거나 병합 값을 해당 셀에 반복 표기

### PDF / doc / docx 처리

1. Read 도구로 파일 읽기
2. 기능명: 파일명에서 추출 (확장자 제거, 공백→`_`, 특수문자 제거)
3. 읽은 내용 그대로 원문으로 사용 → `analysis.md` 작성

### Excel (xlsx/xls) 처리

```bash
{NODE_PATH} -e "
const XLSX = require('xlsx');
const wb = XLSX.readFile('[파일경로]');
wb.SheetNames.forEach(name => {
  const csv = XLSX.utils.sheet_to_csv(wb.Sheets[name]);
  console.log('=== Sheet: ' + name + ' ===');
  console.log(csv);
});
"
```

> xlsx 모듈 없을 시: `cd {PROJECT_ROOT} && npm install xlsx` 후 재실행.

### 기능명 추출 규칙

1. **파일명 우선**: 확장자 제거 후 공백→`_`, 특수문자 제거
2. **내용에 제목 있을 시**: 문서 첫 줄/헤딩이 있으면 그것을 기능명으로 사용
3. 불명확한 경우 파일명 그대로 사용

## 1.4 이미지 분석 (텍스트 선행 2-pass 방식)

Confluence 이미지는 `confluence_image_downloader.py`로 다운로드 후, **텍스트 분석 결과를 컨텍스트로 삼아** 이미지 해석. 이미지 단독 분석 금지 — 텍스트가 만든 Part A 섹션에 이미지를 맞춰 보완하는 방식.

**Pass 1 (다운로드 + 텍스트 작성)**: 이미지 Read 금지. 다운로더가 `images/<원본 파일명>` 또는 파일명 없으면 `image_<url md5 16자리>.png`로 저장 (결정론 — 재실행에도 동일 이름). 텍스트 기반으로 Part A/B/C를 작성하되, 이미지가 등장하는 모든 위치에 플레이스홀더 삽입:
```markdown
> [IMG: <파일명>] (보류 — Pass 2에서 채움)
```

**Pass 2 (컨텍스트 기반 이미지 분석)**: 각 플레이스홀더에 대해 앞뒤 ±500자 텍스트(= 문맥)를 추출하고 `Read(images/<파일명>)`로 이미지 로드. 텍스트에 이미 설명된 내용은 **재추출 금지**, 텍스트에 없는 시각 정보(UI 배치/색상/아이콘/연출/수치 라벨)만 보완. 플레이스홀더를 아래 형식으로 치환:
```markdown
> [IMG: <파일명>] — 섹션: A-2 캐릭터 선택 UI
> - 시각 보완: {텍스트에 없는 정보만}
> - 원본: images/<파일명>
```

**실패/특수 케이스**:
- 다운로드 실패 → `[IMG: <파일명> — 다운로드 실패, 원본 확인 필요]`
- 분석 실패(손상/판독 불가) → `[IMG: <파일명> — 분석 불가]`
- alt에 `.gif`/`.mp4` 포함 → `[IMG: <파일명> — 연출 참조 필요, 정적 스냅샷만 분석]`

> **설계 반영**: 위 3개 실패/특수 케이스가 포함된 소분류는 tc_design.md에서 `[이미지 참조 필요]` 태그 부여 (설계 Step 8 "분석 결과 사전 로딩"의 이미지 플레이스홀더 스캔에서 자동 처리).

### 배치·좌표 서술 가드 (7차 회고 유형 A — 2026-07-28) ⚠ [CRITICAL]

위치·정렬·좌표 정보는 **근거를 인용할 수 있을 때만** 기재한다. 근거 = ①기획서 원문 텍스트 ②Pass 2 이미지 분석 결과(치환 블록에 명시된 시각 보완) 둘 중 하나.

1. **대상 표현**: 방향어(`좌측/우측/중앙/상단/하단/위/아래` 등) · 좌표(`N행 M열`, `[N,M]`) · 정렬(`정렬/배치/배열` + 방향).
   - ⚠ **좌표 표기 형식은 Confluence 컨버터 버전에 따라 달라진다** — 같은 페이지가 `\[3,2\]`(이스케이프)로도 `[3,2]`(비이스케이프)로도 수집된다(2026-07-28 훈장 v115 실측: 구본 이스케이프 5건 → 신본 비이스케이프 5건, 값은 동일). **두 형식을 모두 탐지**하고, 어느 쪽이든 원문에 좌표가 있으면 "이미지에만 있는 정보"가 아니다.
2. **창작 금지**: 원문·이미지 어디에도 없는 배치 정보를 **인접 문장의 패턴으로 메우지 않는다** (훈장 042 사례 — 041의 "좌측 뒤로가기/우측 나가기" 구도를 끌어와 메뉴 이름 위치를 "좌측"으로 단정). 근거 없는 항목은 `[이미지 확인 필요]` 마킹 후 **방향어·좌표 없이** 서술한다: "메뉴 이름이 좌측에 출력" → "메뉴 이름이 출력".
3. **오독 방지**: 원문에서 좌표를 읽을 때 **행·열 순서를 원문 표기 그대로 보존**한다 (훈장 193·194 사례 — 원문 `\[3,2\]` 실존, 행·열을 반대로 전사). 이스케이프 형식도 좌표 표기로 취급해 탐지에 포함한다.
4. **설계 전파**: `[이미지 확인 필요]` 마킹 항목이 포함된 소분류는 `[이미지 참조 필요]` 태그와 동일 취급 — 설계 케이스·재현스탭에서 방향어·좌표 수치 사용 금지.
5. **상호작용 동사도 같은 규칙 (7차 회고 유형 D)**: 기획서에 개폐·호버·포커스·재표시 등 **상호작용 명세가 없는데** "일반적인 UI라면 이렇게 동작할 것"으로 케이스를 만들지 않는다. 근거 없으면 케이스 생성 대신 "기획 확인 필요 항목"으로 승격한다.

> **기계 배선 (2026-07-28)**: `tc-team/lib/origin_gate.js`가 S4 직전에 F열을 원문과 대조해 `$WORK/origin_report.json`을 만든다 — ①`interaction_verb`(HIGH): 그 동작 어간이 원문에 0건 ②`coordinate`(HIGH): 좌표값 미존재 또는 행·열 뒤바뀜 ③`direction`(LOW): 방향어가 원문에 아예 없음. **후보 추출기이지 판정기가 아니다** — 방향어 토큰은 원문에 흔히 실존해(훈장 실측 37회) 이진 판정하면 042형 창작을 놓치고 정당 표현을 오탐한다. 판정은 S4 crossref 렌즈·판정자가 원문 문맥으로 한다.

## 1.5 작업 흐름 (Step 1~7)

1. **입력 유형 판별** → Confluence/PDF/doc/Excel 기준 처리 (§1.3)
   - **파이프라인 모드**: `confluence_raw.md` 존재 시 직접 읽기 (MCP 재호출 금지)
2. **기능명 추출** (공백→`_`, 특수문자 제거)
3. **이미지 다운로드만 실행** (이미지 존재 시):
   - `confluence_image_downloader.py` 실행 → `images/<원본 파일명>` 또는 파일명 없으면 `image_<url md5 16자리>.png`로 저장 (결정론)
   - **이 단계에서 이미지를 Read로 읽지 않는다** (Pass 2에서 처리)
   - 다운로드 실패 이미지는 목록 기록 → Pass 1에서 `[IMG: <파일명> — 다운로드 실패]` 표기
4. **기존 파일 확인**: `ls "$SPECS/[기능명]/analysis.md"` — 있으면 재사용, 없으면 신규 작성. 드라이브 `DX-*_분석_text_1.md` 존재 시에도 로컬 analysis.md 재생성.
5. **Pass 1 — 텍스트 기반 1차 작성** (상세: §1.4 Pass 1):
   - 메타데이터 → Part A(플레이스홀더 삽입, 이미지 Read 금지) → Part B(B-0~B-9) → Part C(C-1, C-2) 순 append
   - 메타데이터 `이미지 개수`는 `N장 (분석 완료: 0장)` 초기 기록
   - 모두 작성 후 파일 1차 저장
6. **Pass 2 — 이미지 플레이스홀더 치환** (상세: §1.4 Pass 2):
   - 각 `[IMG: <파일명>]`에 앞뒤 ±500자 문맥 추출 + `Read(images/<파일명>)` → 텍스트에 없는 시각 정보만 Edit 치환
   - 완료 후 메타데이터 `이미지 개수` → `N장 (분석 완료: M장)` 업데이트 + 최종 저장
7. **candidates.json 방출 + 자체 검증 체크리스트 실행** (§2.5 직렬화 + §1.6, 설계 단계 시작 전 필수)

## 1.6 자체 검증 체크리스트 (Step 7)

아래 항목을 모두 통과해야 분석 단계 완료로 간주. **하나라도 실패 시 해당 Part 재작성 또는 Pass 2 재실행.**

```markdown
[메타데이터]
[ ] 기획서 URL / 해시 / 기능명 / 분석일시 기록됨
[ ] 이미지 개수(총/완료) 표기됨 — Pass 2 완료 후 `분석 완료: M장` 업데이트됨

[Part A — 원문 정리본]
[ ] A-1 개요 작성됨
[ ] A-2 기능 정의 — 기획서의 모든 상위 섹션 반영
[ ] A-3 이미지 분석이 본문 플레이스홀더 자리에 인라인 치환됨
[ ] `[IMG: ...] (보류 — Pass 2에서 채움)` 미치환 플레이스홀더가 남아 있지 않음 (파일명 무관 — `(보류 — Pass 2에서 채움)` 마커 문자열로 검사; 다운로드 실패/분석 불가 명시는 허용)
```

## 2.5 Part B — 테스트 분석 레이어 (후보 식별)

> 이 Part는 **후보 목록**만 작성. 실제 테이블/매핑은 tc-설계.md 담당.

**B-0. 소분류 마스터 키 표** (전개기 조인 키 — 2026-06-12 신설) — Part B 전체가 참조하는 소분류의 **단일 명명 원장**. 컬럼: `key | 소분류명 | 비고`
- `key`: 영소문자 스네이크(`^[a-z0-9_]+$`), 의미 기반 명명 (예: `skill01_charge`). 중복 금지.
- B-3~B-9의 소분류 표기는 **B-0의 소분류명과 문자열 동일**해야 함 (동의어·축약 변형 금지 — 런 간 명명 표류가 기계 조인을 깨뜨린 원인)
- candidates.json의 모든 subcat 참조가 이 키로 조인됨 — 미등재 키 참조는 candidate_schema.js S-21/31/41로 fail-fast

**B-1. 용어 사전** — 기능 고유 용어 표. 컬럼: `용어 | 정의 | 동의어/관련`. 없으면 "해당 없음".

**B-2. 외부 의존성 & 연계 기능** — 외부 시스템/데이터/연계. 컬럼: `# | 의존 대상 | 유형 | 등장 섹션 | 관계 유형 (1:1/1:M/M:N)`

**B-3. EP 파티션 후보** (동등 분할) — 수치/상태/입력 조건 있는 소분류에 유효/무효 파티션 식별. 유효는 1건 대표, 무효는 **실패 사유별**로 분리. 컬럼: `# | 소분류 | 입력/조건 | 유효 파티션 | 무효 파티션 (분리 사유)`
> **candidates.json 직렬화 (Phase B)**: `ep[] = {subcat, condition, partitions:[{kind: valid|invalid, label, expect}]}`. **B-4 포인트·B-5 전이·B-6 결정과 중복되는 파티션은 생략**(MD 표에는 `→B-4` 식 참조 표기) — 전부 중복이면 ep 항목 자체를 생략. expect는 검증 절 한 줄.

**B-4. BVA 후보 수치** (경계값 분석) — 수치 제한 소분류의 4포인트 (`min-1` / `min` / `max` / `max+1`). 실제 TC는 설계 단계에서 작성. 컬럼: `# | 소분류 | 수치 출처 (GlobalDefine 키) | 현재값 | min-1 / min / max / max+1`. 참조: §3.3 경계값 참조표
> **셀 문법 강제 (2026-06-12)**: 4셀 전부 채움 — 각 포인트는 `값(라벨)` **1방향 1셀** (상·하한 통합 표기 금지). 불가 포인트는 빈칸·`—`가 아니라 `skip(infeasible|unspecified): 사유` 명기 (예: min=max 동일값, 음수 불가, 미지정). 유효 포인트 2개 미만이면 BVA 후보가 아님 — C-1(미지정) 또는 B-3(EP)으로 보냄. v3 "하한/상한" vs v4 "min-1/min/max/max+1" 표류(행수 19↔12)가 본 문법 고정의 근거.

**B-5. 상태 머신 후보 목록** — 상태 있는 소분류 식별 + 기본 상태/트리거 스케치. 실제 전이 테이블은 tc-설계.md (EVAL-12)에서 완성.
- 대상 판별 기준: 활성/비활성 토글, 시간 기반 전이(쿨타임/카운트다운), 진행 단계(퀘스트/강화), 자원 소모(내구도/스택), 잠금/해제
- 컬럼: `# | 소분류 | 상태 종류 | 주요 트리거 | 복잡도`
> **candidates.json 전이 전수 명시 (2026-06-12)**: MD 표는 스케치 유지하되, candidates.json `fsm[]`에는 `states[]` + `transitions[]`(from/to/trigger)를 **전수 열거** — all-edges 전개(전이당 정확히 1케이스) 입력. 전개기 Phase C 합류 시 설계 EVAL-12 전이 테이블은 이 projection으로 대체 예정.

**B-6. 결정 테이블 후보 목록** — 복합 조건(2개 이상 AND/OR) 소분류 식별. 실제 매트릭스는 tc-설계.md (EVAL-13)에서 완성.
- 대상 판별 기준: "A이고 B이면", "A이거나 B이면", 복수 조건 동시 체크
- 컬럼: `# | 소분류 | 조건 개수 | 조건 목록 | 결정 결과 유형`
> **candidates.json 직렬화 (Phase B)**: `decision[] = {subcat, name, op: AND|OR, conditions:[2개+], true_outcome, false_outcome}` — **단층만** (중첩 식은 항목 분리). MC/DC 전개로 c조건 → c+1 케이스 자동 생성 (2^c 전조합 불필요). 다수 인자 조합(3개+ 독립 인자 × 수준)은 `pairwise[] = {subcat, name, factors:[{name, levels:[2개+]}]}`로 — covering array가 전조합 대신 쌍 커버 최소행 생성. 수치 경계 분기(1/2/3회 등)는 decision이 아니라 B-4로.

**B-7. 암묵적 요구사항 태그 매핑** — **모든** 소분류 전수 나열 + 태그 부여. 빈 셀 금지 ("해당 없음" 명시). 컬럼: `소분류 | 적용 태그 | 근거 (한 줄)`. 태그 카탈로그: §3.1 참조
> 태그 후보: `[세션] [권한] [데이터] [UI] [유저상태] [동시성] [대소문자] [시간조작] [연계]`

**B-8. 오류 패턴 매칭 (Error Guessing)** — 각 소분류를 §3.2 "오류 추정 카탈로그" 행과 대조. 컬럼: `소분류 | 매칭 기능 유형 | 반영 필요 오류 패턴 | 비고`
> **설계 반영 필수**: 각 행은 tc_design.md "분류 그룹핑 트리"의 해당 소분류 `→ 부정/예외` 케이스로 승격. 설계 Step 8에서 B-8 스캔 후 반영 누락 시 케이스 보강.
> **enum 강제 (2026-06-12)**: candidates.json `patterns[]`의 `type`은 §3.2 enum 7종(`qty_change` `state_transition` `time_based` `conditional_lock` `list_search` `text_input` `integration`)만, 패턴 id는 `scripts/util/expander/pattern_catalog.js` 카탈로그만 허용. 위반은 S-42/44 fail-fast (오류 메시지에 허용 목록 포함).

**B-9. 다관점 렌즈 스윕 매트릭스** — **모든 소분류 × §3.5 렌즈 8축** 격자. **빈칸 금지.** 각 칸: 해당 시 도출 후보(한 줄), 비해당 시 `– (사유)`. 기존 B-3/B-4/B-5/B-8에서 이미 도출한 축은 `→B-4` 식 참조로 갈음하고, **신규 축(L3 반복/멱등·L4 생명주기·L1 개수경계 확장)은 여기서 신규 도출.**
> **candidates.json 직렬화 (Phase B)**: `lenses[] = {subcat, axis: L1~L8, candidate: "검증 절 한 줄"}` — **신규 도출 칸만** (→참조 칸·`–` 칸 생략). candidate는 "…는지" 형태의 검증 가능한 절로 (격자 셀의 키워드 스케치를 절로 완성해 직렬화).

```markdown
| 소분류 | L1 개수 | L2 빈/널 | L3 반복 | L4 생명주기 | L5 동시성 | L6 중단 | L7 역방향 | L8 세션 |
|--------|--------|---------|---------|-----------|----------|---------|----------|---------|
| [소분류명] | 0/1/max±1 | –(표시전용) | 연속클릭 차감 | 닫을때 잔류 | →B-8 | →B-8 | 미충족 차단 | –(시간무관) |
```

> **목적**: "각 소분류를 8각도로 모두 검토했다"를 격자로 강제. **빈칸(미검토)이 0**이어야 누락 방지 성립. 해당/비해당 판단 자체가 산출물 — 비해당 사유가 곧 "따져보고 제외했다"는 증거.
> **설계 반영 필수**: 해당(비-`–`) 칸은 tc_design.md 분류 트리 `→` 케이스로 빠짐없이 전개. 설계가 압축하면 안 됨(생성측 누락 차단, 검수 C-12와 짝).
> **조건부**: 무조건 8케이스가 아님 — 해당 칸만 TC가 된다(§3.5 조건부 도출 원칙).

**B-10. 미구성 항목 목록 (데이터 시트 대상 행 값 미보유)** ⚠ [조건부·직렬화 제외] — 데이터 시트(표) 입력일 때만. §3.7 규정에 따라 컬럼 '일반 설명'이 특정 대상 행에 적용되지 못하는(해당 셀 공란) 항목을 기록. 컬럼: `# | 대상(행/Index) | 컬럼 | 근거(공란 확인)`. **여기 등재 항목은 TC 후보 승격 금지** (이번 마일스톤 미구성). 데이터 시트 입력이 아니면 "해당 없음".
> **직렬화 제외**: B-1·B-2·B-7과 동일하게 candidates.json에 넣지 않는다 (candidate/LENS 스키마 무관).

### Part B 직렬화 — candidates.json 방출 (결정론 전개기 입력 계약, 2026-06-12 Phase A)

Part B 완성 직후(Pass 2 반영 후), B-0/B-4/B-5/B-8을 **동형 JSON**으로 직렬화해 `[specs]/candidates.json` 저장.

- **스키마**: `{ meta{feature, version:1, source}, subcats[]←B-0(+선택: cat1/cat2/risk/platform 렌더 그룹핑), bva[]←B-4(4포인트, skip 객체 허용), fsm[]←B-5(states+transitions 전수), patterns[]←B-8(type enum+패턴 id), ep[]←B-3(중복 생략), decision[]/pairwise[]←B-6(단층 AND/OR·조합 인자), lenses[]←B-9(신규 도출 칸만) }`. 예시 실물: `tests/fixtures/candidates_boss0011_v4.json`
- **검증 (필수)**: `node {PROJECT_ROOT}/scripts/util/expander/candidate_schema.js [specs]/candidates.json` → **exit 0**. exit 4면 violations의 JSON path를 수정 후 재실행 (fail-fast 루프 — 직렬화 실패를 분석 단계 안에서 소진)
- **표↔JSON 행수 대조**: 검증 출력 `counts`의 `subcats / bva_rows / fsm_rows / pattern_rows / ep_rows / decision_rows`가 MD 표 행수와 일치해야 함 (불일치 = 표 또는 JSON 누락. ep/lenses는 중복 생략 계약 때문에 MD 표 행수 **이하** 허용)
- **산출 의무만 — 소비(설계 전개·렌더)는 전개기 Phase C 파이프라인 합류 시 시작** (전개·렌더 체인은 오프라인 관통 증명 완료: expand.js → render_design.js → direct_convert exit 0).

## 2.6 Part C — 설계 힌트 (분석 고유 정보만)

> 리스크/TC 배분은 설계 단계가 원문 기반으로 직접 결정하므로 분석에서 초안을 만들지 않는다. Part C는 **설계가 원문만 읽어선 알 수 없는 정보**만 담는다.

**C-1. 미지정값 재확인 체크리스트** — `N (미지정)`, `TBD`, `시간 (미지정)` 전수 추출. 컬럼: `# | 키/항목 | 등장 위치 | 현재 상태 | 재확인 필요 여부`
> **설계 반영 필수**: 모든 항목은 tc_design.md "GlobalDefine 키 목록" `미지정` 컬럼에 `⚠` 표기 + 메타데이터 바로 아래 **"기획 확인 필요 항목"** 블록으로 승격. tc-writer는 해당 키 참조 TC에서 구체 수치 대신 **사람 언어 주어 + 키 괄호 병기**(예: `삭제 제한 레벨(Character_DeleteLevelLimit, 미지정) 미만 캐릭터 삭제 시 차단`)로 재현스탭 작성. ⚠ **미지정 키를 문장 첫 주어로 raw 노출 금지** — `Character_DeleteLevelLimit 미만 캐릭터 삭제…` 식으로 키가 주어가 되면 식별자 주어화 위반(소환권 v6 025 사례: `Sample_HighGradeCondition(N=미지정) 등급 이상…`이 검수에서 누락). 값 결정 시 TC 수정 없이 GlobalDefine만 갱신.

**C-2. 분석자 코멘트 (모호/불명확 지점)** — Opus가 발견한 해석 모호 지점 기록. 1차/2차 리뷰 이슈 근거. 컬럼: `# | 섹션 | 모호 지점 | 가정 | 리뷰 확인 필요`

## 3.2 오류 추정 카탈로그 (Error Guessing)

기능 유형별로 자주 누락되는 오류 패턴 목록. tc_design.md 작성 시 소분류를 기능 유형에 대조하여 해당 패턴 반영 여부 확인.

| 기능 유형 | 연관 암묵적 요구사항 태그 | 자주 누락되는 오류 패턴 | tc_design.md 반영 방법 |
|---------|---------------------|------------------|-------------------|
| 수량/재화 변경 `qty_change` | `[데이터]` `[동시성]` | 동시 요청 중복 소모, 음수/0 입력, 롤백 없는 실패, 최대치 초과 소모 | `[동시성]` 태그 + BVA 4포인트 |
| 상태 전이 `state_transition` | `[세션]` `[데이터]` | 중간 상태에서 앱 강제 종료, 네트워크 끊김 후 상태 불일치, 동일 이벤트 재발생(비정상 전이) | 상태 전이 테이블 작성 + 예외 행 포함 |
| 시간 기반 기능 `time_based` | `[시간조작]` `[세션]` | 클라이언트 시간 조작, 자정/주간 갱신 경계, 앱 백그라운드 중 시간 경과 | `[시간조작]` 태그 + 경계 시점 TC 명시 |
| 조건부 잠금/해제 `conditional_lock` | `[권한]` `[연계]` | 조건 변경 직후 캐시 미반영, 복수 조건 중 하나만 충족, 조건 충족 후 재잠금 여부 | 결정 테이블 작성 + `[권한]` 태그 |
| 목록/검색/페이지네이션 `list_search` | `[UI]` `[데이터]` | 빈 목록(0건), 최대 항목 수 도달, 마지막 페이지 경계, 정렬 기준 변경 후 유지 여부 | NULL/빈상태 대상 목록 + BVA |
| 텍스트 입력 `text_input` | `[대소문자]` `[데이터]` | 최대 길이 초과, 특수문자/이모지 입력, 공백만 입력, 복사-붙여넣기 | BVA 최대 길이 + `[대소문자]` 태그 |
| 연동/인터페이스 `integration` | `[연계]` `[데이터]` | A 기능 완료 후 B 화면 미반영, 연동 기능 삭제 후 참조 오류, 순서 의존성 역전 | 기능 간 관계 테이블 + 교차 TC 명시 |

> **enum id (2026-06-12)**: 백틱 id는 candidates.json `patterns[].type` 허용값 — 코드 SSoT는 `scripts/util/expander/pattern_catalog.js` (패턴 id 목록 포함). 이 표와 카탈로그의 유형 7종은 1:1.

**사용 방법**:
1. tc_design.md 소분류 작성 시 위 표에서 해당 기능 유형 행을 찾아 대조
2. 오류 패턴이 소분류 설명 또는 검증단계 배분표에 반영됐는지 확인
3. 반영 안 됐으면 해당 소분류에 추가 (부정/예외 케이스로 보강)

> 암묵적 요구사항 태그와 1:1 연결됨 — 태그 붙은 소분류는 반드시 해당 행의 오류 패턴 검토.

## 3.5 범용 검증 렌즈 8축 (B-9 스윕용 — 도메인 무관 사고축)

기능 유형(§3.2)이 "무엇을 하는 기능인가"라면, **렌즈는 "어떤 각도로 깨지는가"**를 묻는 도메인 무관 사고축이다. 각 소분류를 8축으로 **빠짐없이 질의**하여, **해당하면** 검증 후보를 도출하고 **비해당이면 사유**를 남긴다(B-9 매트릭스). 목적은 **"안 따져봐서 누락"을 "따져보고 제외"로 전환**하는 것.

| # | 렌즈 | 질의 (이 소분류에 …) | 해당 시 도출 예 | 연결 |
|---|------|------|------|------|
| L1 | **개수 경계** | 수량·**목록/탭/그룹 개수**·길이가 있나? | 0 / 1 / min-1·min·max·max+1 | B-4 |
| L2 | **빈/널** | 0건·미선택·미입력·결과 없음 상태가 가능한가? | 빈 상태 표시/안내 | B-3·NULL목록 |
| L3 | **반복/멱등** | 연속 입력·N회 반복·재실행이 가능한가? | 연속클릭 중복방지 / N회 독립성 / 중복결과 허용 | (신규) |
| L4 | **생명주기** | 열림→닫힘·진입→이탈·부모-자식 관계가 있나? | 닫을 때 자식/오버레이 잔류·딤드 해제·연출 후 출력 | (신규) |
| L5 | **동시성** | 동시 요청·경쟁·롤백이 가능한가? | 동시 중복 차감 / 롤백 실패 | B-8 |
| L6 | **상태 중단** | 강종·네트워크 끊김·백그라운드 영향이 있나? | 중간 중단 후 정합성/보존 | B-8·[세션] |
| L7 | **역방향/제약** | 조건 미충족·권한 없음·잘못된 경로·오입력? | 차단/거부/경고 | B-3 무효 |
| L8 | **세션/시간** | 로컬 시간·갱신주기·세션 만료 의존이 있나? | 시간 조작·경계 시점 | [시간조작]·[세션] |

> **조건부 도출 원칙 (CRITICAL)**: 무조건 8케이스가 아니라 **해당 축만** 케이스화한다. 대부분의 소분류는 일부 축만 해당하고 나머지는 "비해당". 비해당 칸은 **빈칸이 아니라 사유 한 줄**(예: "표시 전용, 입력 없음 → L3 비해당"). TC 폭증 방지 + 검토 누락 방지를 동시에.
> **신규 축(L3·L4) + 확장(L1 개수)**: 소환권 v2·v4 누락(연속클릭·독립추첨·등급탭 0/1개·오버레이 잔류)이 기존 §3.1/§3.2로 안 잡힌 사각 — 본 렌즈로 정조준.
> **분해(d) 짝**: 기획서에 **명시됐는데 도출 안 된 규칙**(예: 확률 반올림 보정·가변 소수점)은 렌즈가 아니라 **커버리지 매핑표의 규칙단위 분해**로 잡는다(tc-설계.md). 렌즈(엣지)+분해(명시규칙)가 함께 덮는다.

## 3.9 QA 스코프 지시서 ⚠ [조건부]

> **발동 조건**: `$SPEC/qa_scope.md` 가 존재할 때만. 없으면 이 절 건너뜀(기본값 — 기획서 전 범위).

QA 리드가 이번 TC의 **검증 범위**를 좁혀둔 파일이다. 기획서가 다루는 내용이라도 **범위 밖으로 지정됐으면 후보로 승격하지 않는다.**

- **읽는 순서**: 기획서보다 **먼저**. 무엇을 볼지 정한 뒤에 원문을 읽어야 범위 밖 항목이 트리에 안 들어온다.
- **⛔ 목록은 강제**: "만들지 말 것"으로 지정된 유형은 Part B 후보에서 제외한다. 기획서에 근거가 있어도 마찬가지 — 근거 유무가 아니라 **범위**의 문제다.
- **출처 표기 의무**: 지시서가 타 기획서 내용을 참고로 싣고 있으면, 그것을 근거로 쓴 값에 `(출처: <지시서가 명시한 원 출처>)` 를 병기한다. **지시서 자체를 출처로 적지 말 것** — 지시서는 기획서가 아니다.
- **범위 확장 금지**: 지시서의 참고 자료에만 있고 이번 기획서가 다루지 않는 기능은 TC 후보가 아니다(배경 지식일 뿐).
- **판정 불가는 그대로**: 지시서로도 판정이 안 되면 추론하지 말고 `[근거부족—기획질의]`.

> **근거**: 2026-08-06 기능B 런. 스코프가 "스탯이 노출되는가"였는데 설계는 "스탯 수치가 실제로 오르는가"로 나왔다 — 대분류 6개 중 3개(168줄)가 전투 수치 검증, 노출은 11줄. 기획서만 보면 데이터 대조표라 수치 검증으로 읽히는 게 자연스러웠다. **스코프를 기계에 전달할 경로가 없어** S3 직전에 런을 세워야 했고, 그래서 이 절이 생겼다.

## 3.10 본문 내 비요구사항 절 (레퍼런스·AS-IS) ⚠

> **발동 조건**: 항상. §3.8이 *밖에서 가져온 문서*를 다룬다면, 이 절은 **본문 안에 이미 들어와 있는 비요구사항**을 다룬다. 링크와 달리 수집 단계가 없어 배제 장치가 필요하다.

기획서의 모든 절이 요구사항인 것은 아니다. 절을 3종으로 판별해 **TO-BE만 후보로 올린다.**

| 성격 | 판별 신호 | 처리 |
| --- | --- | --- |
| **TO-BE** (요구사항) | "~한다 / ~적용한다" — 우리 게임의 앞으로의 동작 | 소분류·TC 도출 |
| **AS-IS** (현행 서술) | "기존/현재 규칙은 ~" + 같은 문서가 개선안을 별도 절로 제시 | **TC 금지** |
| **레퍼런스** (타사 조사) | 타 게임·경쟁작·외부 사례 비교표 | **TC 0건** |

- **TC 후보 승격 금지**: 근거 유무가 아니라 **범위**의 문제다(§3.9와 같은 논리). 본문에 버젓이 있다는 것이 승격 사유가 되지 않는다.
- **AS-IS를 TC로 만들면 전량 FAIL한다**: 같은 문서의 TO-BE 절이 그 동작을 대체하기 때문. 개선안이 제시된 절의 현행 서술은 **회귀 비교 컨텍스트로만** 쓴다.
- **공백 탐지기로는 쓴다**: 레퍼런스 표의 `특이사항`·비교 항목 중 **TO-BE 절이 답하지 않는 것**은 C-1 미지정 후보로 올린다. 버리라는 뜻이 아니다.
- **⛔ 질문에 레퍼런스를 인용하지 말 것**: M열에는 우리 기능의 질문만 나간다. `오딘은 자동이던데 우리도 자동인가요` (X) → `정렬 갱신은 자동입니까, 사용자 입력입니까` (O). 라벨링_기준.md ⛔표 동일 취지.
- **Part A 표기 의무**: Part A는 원문 보존이므로 절은 그대로 옮기되, 해당 절 heading 끝에 `[비요구사항: 레퍼런스]` 또는 `[비요구사항: AS-IS]` 태그를 단다. **이것이 Part B 도출에서 제외됐음을 보이는 유일한 기계 흔적이다**(`grep -c "\[비요구사항:"`).
- **B-10과 다르다**: B-10 미구성 항목은 *데이터가 빈 우리 기능*, 여기는 *애초에 우리 기능이 아닌 것*. 섞어 기록하지 말 것.

> **근거**: 2026-08-19. 인벤토리 개선 1차(<PAGE_ID>)는 3장이 §3-1 기존 정렬 방식 / §3-2 레퍼런스 게임 정렬 방식(오딘·리니지W) / §3-3 신규 정렬 방식으로 나뉘고 **TC 대상은 §3-3뿐**이다. 그런데 이를 막는 규칙이 rules 9종 전체에 없었다 — 링크 유래에는 §3.8 "범위 확장 금지"가 있으나 **본문 내 절에는 대응 장치가 없어 LLM 판단에만 걸려 있었다.** 사고가 안 난 것은 규칙이 막아서가 아니라 표가 명백히 타사 얘기였기 때문이고, 그것은 보장이 아니다.
