# TC 설계 검수 운용 지침

모든 답변과 보고는 **한국어**로 작성한다.

---

## 역할

STEP 1(설계) 결과물이 tc-설계.md 기준에 부합하는지 검수.

- 입력: `analysis.md` + `tc_design.md` (specs/[기능명]/ 내)
- 기준: `{CLAUDE_HOME}\tc-team-v2\skills\tc-설계\tc-설계.md`
- 출력: `design_review.md` + `step_result.json`

---

## 검수 전 준비

```
1. specs/[기능명]/analysis.md 읽기
2. specs/[기능명]/tc_design.md 읽기
3. specs/[기능명]/confluence_raw.md 읽기 (기획서 원문 비교용)
4. tc-설계.md 읽기 (검수 기준 확인)
```

## 검수 항목 (C-01 ~ C-14)

### C-01 파일 완결성 [CRITICAL]
- analysis.md 존재 + 내용 있음
- tc_design.md 존재 + 내용 있음
- 둘 다 없거나 비어있으면 CRITICAL

### C-02 분류 구조 [CRITICAL]
- 대/중/소분류 3계층 tc_design.md에 명확히 정의
- 소분류 없는 중분류 또는 중분류 없는 대분류 → CRITICAL
- 소분류 3개 미만인 중분류 → MEDIUM

### C-03 분류 그룹핑 트리 [HIGH]
- tc_design.md에 "## 분류 그룹핑 트리" 섹션 존재
- 형식: `대분류 → 중분류 → 소분류 [리스크레벨] [플랫폼]` 계층
- 누락 → HIGH

### C-04 기본기능 섹션 [HIGH]
- tc_design.md에 "## 기본기능 검증 항목" 섹션 존재
- 항목 1개 이상
- 누락 → HIGH

### C-05 커버리지 완성도 [HIGH]
confluence_raw.md와 tc_design.md 분류 트리 비교 → 아래 10개 영역 누락 확인:

| # | 영역 (기획서에 존재 시만 체크) |
|---|------|
| 1 | 검색 기능 |
| 2 | 예외처리 전용 섹션 |
| 3 | 알림/뱃지 상세 동작 |
| 4 | 다른 기능에서의 진입점 |
| 5 | 연결 이동 기능 |
| 6 | 추천/자동화 알고리즘 |
| 7 | UI 안내/팁 요소 |
| 8 | 추후 구현 항목 |
| 9 | 목록 내 탭/필터 |
| 10 | 플랫폼 전용 조작 |

기획서에 해당 영역 존재 + 분류 트리에 없음 → HIGH 1건씩 기록.

> ⚠ **분모 완전성 교차 확인 (자기참조 사각 방지, 2026-06-12)**: 위 10개 영역과 커버리지 매핑은 "설계자가 추출한 목록"이 분모이므로, 추출 단계에서 빠진 항목은 매핑률 100%여도 검출되지 않는다. 반드시 tc-학습.md 활성 설계 패턴(특히 **P-18** 상호작용 매트릭스 / **P-19** 서술형 섹션 분해 / **P-20** BVA 상·하한 분리)으로 confluence_raw.md 원문 대비 분모 자체의 누락을 교차 검사할 것 — 위반 시 HIGH (근거: 보스 TC run v2 — 자동사냥 섹션 통째 누락·상태이상 매트릭스 전멸이 C-05/C-12 전부 통과).

### C-06 GlobalDefine 키 목록 [HIGH]
- confluence_raw.md에 GlobalDefine 키 있을 때
- tc_design.md에 "## GlobalDefine 키 목록" 섹션 존재 필요
- 기획서에 없으면 SKIP
- 누락 → HIGH

### C-07 암묵적 요구사항 태그 [MEDIUM]
- tc_design.md 소분류에 암묵적 요구사항 태그 부여 여부 — 태그 목록은 **tc-분석.md §3.1 카탈로그(9종)** 단일 소스 참조 (하드코딩 금지)
- 서버 로직 있는 기능에 태그 0개 → MEDIUM

### C-08 취소선 처리 [MEDIUM]
- confluence_raw.md에 취소선(`~~텍스트~~`) 있을 때
- analysis.md에 동일 `~~텍스트~~` 형식 반영 여부
- tc_design.md에 "추후 구현" 처리(비고=추후 구현, 결과=N/A) 여부
- 미처리 → MEDIUM

### C-09 플랫폼 태그 [MEDIUM]
- tc_design.md 분류 트리 소분류에 [PC/모바일] / [PC] / [모바일] 태그
- 태그 없는 소분류가 전체 20% 이상 → MEDIUM

### C-10 리스크 레벨 태그 [LOW]
- tc_design.md 분류 트리 소분류에 [HIGH] / [MEDIUM] / [LOW] 태그
- 태그 없는 소분류가 전체 30% 이상 → LOW

### C-11 원천 → 트리 링크 검증 [HIGH]
원천 섹션(트리 앞 8종) 각 항목이 **분류 그룹핑 트리의 `→` 케이스에 1회 이상 등장**하는지 기계 대조. 누락 1건당 HIGH 1건.

| # | 원천 섹션 | 검증 질문 | FAIL 조건 |
|---|----------|----------|----------|
| 1 | 섹션 전수 대조표 | 표의 모든 기획서 섹션이 트리 대/중/소분류에 매핑되는가 | 매핑 안 된 섹션 존재 |
| 2 | 취소선/추후구현 항목 | 취소선 항목이 트리에 **없는지**(역체크), 추후구현은 비고 "추후구현" 표기 대상인지 | 취소선이 트리에 존재 |
| 3 | NULL/빈상태 대상 목록 | "예외 TC 필요=O" 항목마다 해당 소분류에 `→ 예외-N` 케이스가 존재하는가 | O인데 `→ 예외` 없음 |
| 4 | 상태 전이 테이블 | 모든 전이 엣지(상태A→상태B)가 트리 `→` 케이스 1개 이상에 매핑되는가 | 미매핑 엣지 |
| 5 | 결정 테이블 | 모든 조건 조합 행이 트리 `→` 케이스에 매핑되는가 | 미매핑 조합 |
| 6 | GlobalDefine 키 목록 | 각 키(미지정 `⚠` 포함)가 최소 1개 트리 `→` 케이스 설명에 등장하는가 | 키가 트리 어디에도 없음 |
| 7 | 신뢰 파괴 위험 요소 | HIGH 체감 시나리오가 트리 `→` 부정/예외 케이스에 반영되었는가 | HIGH 체감 항목 미반영 |
| 8 | 리스크 태깅 비율 | HIGH 소분류 부정+예외 ≥ 60%, MEDIUM ≥ 49%, LOW ≥ 30% (⚠SSoT: tc-설계 기준, 4파일 동기) | 비율 미달 |

추가 역방향 체크:
- B-8 오류 패턴(analysis.md): **C-12로 승격** (HIGH 게이트 — 아래 C-12 참조)
- C-1 미지정값(analysis.md): 각 항목이 "기획 확인 필요 항목" + GlobalDefine `미지정` 컬럼에 승격 → 미승격 시 MEDIUM
- ⚠ **리스크 하향 근거 검증 (비율 회피 차단 — 소환권 v6 사례)**: 리스크가 하향된 소분류(또는 비율 미달인데 리스크 LOW로 통과한 소분류)는 배분표 비고의 `[하향 M→L | 근거]`를 확인 — 근거 없거나 단순성 4조건(상태전이·데이터변경·분기·동시성 모두 없음) 미입증, "비율 충족용" 류 사유 시 **HIGH** (하향 무효 처리 → 케이스 추가 요구). v6: 비율 미달(확률버튼·그룹탭·개별확률)을 리스크 LOW 하향으로 회피해 TC 빈약화된 사례.

> **근거**: tc-설계.md 섹션 순서가 "원천 → 트리 → 배분·검증"으로 재정렬 후, 검수는 단방향(원천→트리) 기계 대조 가능. 학습 근거 P-05(교차 중복), P-08(상태 전이 엣지 누락) 재발 방지.

### C-12 분석 → 설계 전개율 검증 [HIGH] ⚠ (소환권_v2 A형: 설계압축 재발 방지)

analysis.md의 테스트 후보가 tc_design.md 분류 트리 `→` 케이스로 전개됐는지 기계 대조. **C-05(기획 영역=폭)가 PASS여도 이 항목(BVA 깊이=전개)은 별도 게이트.**

**필수 산출물 — 분석후보 ↔ 설계케이스 1:1 매핑표** (design_review.md에 출력. 비율만 적고 끝내기 금지):

|---|---|---|
| B-4 보유량 max+1 (Summon_…Limit) | 트리 `→ 예외-3` | ✓ |
| B-8 연속클릭 중복차감 | (없음) | ✗ |

> **B-9 연동 (2026-06-02)**: 분석이 렌즈 8축으로 도출한 해당 칸을 설계가 빠짐없이 전개했는지 검수에서 재확인 — v5 잔여 누락(C10 아이콘재선택·E12 재소환연속·E04 강조미충족)처럼 *분석엔 있으나 설계가 빠뜨린 것*을 STEP3로 차단. (정답지 커버리지 게이트·kw 정교화·사람 검수는 6차 마일스톤 후 ②검수 라인에서.)

**전개기 완전성 게이트 소비 (결정론 1차 그물, 2026-06-13)** — 핸드오프에 `coverage_gaps.json`이 있으면 **C-12 1:1 매핑표 작성의 기계 사전 패스**로 사용한다:
- `gaps[]` 각 항목 = candidates.json(분석 Part B 직렬화)을 전개기가 결정론으로 펼친 "있어야 할 바닥 케이스" 중 **설계 트리에 대응이 없는 것**. 각 gap에 `subcat / gen / source(B-3~B-9 출처) / floor_case / nearest_design` 포함.
- 처리: gap 1건마다 confluence_raw.md 원문과 대조해 **(a) 진짜 누락 → 케이스 추가 지시 + HIGH 등재**(C-12 `✗` 동급) 또는 **(b) 정당 기각 → 매핑표 `⊘` + 사유 한 줄 명시**. **사유 없는 기각 금지**(`✗`로 강등).
- ⚠⚠ **dup_event 기각 금지 패턴 (P-21, 2026-06-13 v6 실증 — 리뷰어가 2건 오기각)**: `dup_event`(동일 이벤트 재발생 시 **중복 차단/비정상 전이 방지** = 부정)와 **"재피격/재적중 시 지속시간 갱신"(refresh = 정상)** 은 **정반대 의도**다. 갱신 케이스를 근거로 dup_event gap을 기각하는 건 **범주 오류** — 금지. dup_event gap의 정당 기각은 둘 중 하나만 인정: ① 설계에 실제 **"중복 트리거 차단/재발동 방지/무한 루프 차단"** 케이스가 존재, 또는 ② 기획 원문이 그 재이벤트를 **중복 불가능**으로 명시(근거 인용). **내부 일관성 신호**: 같은 기능군의 다른 소분류(부위파괴·그로기·뒤집힘 등)가 dup_event를 케이스로 뒀는데 이 소분류만 없으면 → **설계자 누락(진짜 gap)이지 의도적 면제 아님 → 케이스 추가**(v6: 점프공격·물방울이 이 패턴으로 누락).
- ⚠ 게이트는 텍스트 유사도라 **distinctive 누락**(dup_event·FSM 엣지·렌즈 신규축)에 강하고 형제와 토큰이 같은 단일 경계점 누락엔 약함 — 게이트 gaps=0이어도 C-12 매핑표(특히 B-4 100%)는 **독립 수행**(게이트는 보강이지 대체 아님).
- 게이트는 **비차단**(advisory): gaps 존재 자체는 FAIL이 아니고, 처리 결과(추가 HIGH 또는 사유 기각)가 매핑표에 반영되면 됨.

### C-13 기획서 → 분석 도출 완전성 검증 [HIGH] ⚠ (소환권_v2 B형: 분석누락 재발 방지)

|---|------|------|------|
| 1 | 수치/경계 (최대치·제한·MaxCount·기간·횟수) | B-4 BVA | 수치 1개라도 B-4에 min-1/min/max/max+1 후보 없음 |
| 2 | 상태 전이 (토글·진행단계·시간전이) | B-5 상태머신 | 전이 요소가 B-5에 미식별 |
| 3 | 복합 조건 (A이고B / A이거나B) | B-6 결정테이블 | 조건 조합이 B-6에 미식별 |
| 4 | 저장·재화변경·동시요청 가능 기능 | B-8 오류패턴 | §3.2 해당 기능유형 오류패턴(만석·동시중복·롤백·세션중단)이 B-8에 0건 |
| 5 | GlobalDefine 키 / 토스트 키 | A-5 / B-4 | 기획서 키가 analysis에 누락 |

- **도출률 = (분석에 도출된 검증요소 수 ÷ 기획서 검증요소 수). 100% 미만이면 누락 요소 1건당 HIGH** (STEP 3 트리거)
- ⚠ **B형 누락은 analysis.md 자체를 고쳐야 하므로**, 이슈에 **누락 기획서 요소를 콕 집어 명시**(섹션·수치·키명) → STEP 3 designer가 분석 패치 가능하도록.
- **step_result.json `analysis_gap` = C-13 HIGH 건수**. `>0`이면 팀장이 STEP 3을 **opus 재분석**으로 라우팅(sonnet 설계수정 대신).

> **근거**: 소환권_v2 — 연속클릭 중복차감·만석 등이 analysis 자체에 누락. C-12는 분석에 없는 후보를 검사 못 함(상류 누락). self-review(§1.6)는 동일 에이전트라 사각 발생 → 독립 게이트로 승격. C-13은 "기획서 ↔ 분석"을 직접 대조하는 분석누락 차단 게이트.

### C-14 직변환 기계 게이트 [HIGH] ⚠ (v10: STEP 4 차단 왕복 재발 방지 — 이중 그물)

설계자가 Step 11.5(tc-설계.md)에서 이미 통과시켰어야 하는 게이트의 **독립 재검증**. 기계 실행 — LLM 판단 금지.

```bash
"{NODE_PATH}" \
  "{WORK_ROOT}/scripts/util/direct_convert.js" convert \
  "{WORK_ROOT}/team/specs/[기능명]/tc_design.md" \
  "{WORK_ROOT}/team/specs/[기능명]"
```

- **exit 0** → PASS (생성된 tc_skeleton.json 잔존 무해 — STEP 4가 폐기·재생성)
- **exit 4** → `conversion_blocker.json`의 건별 내용(유형·line·본문)을 **이슈 목록에 HIGH로 전수 등재** + **needs_fix=true 강제**. ⚠ blocker 파일은 삭제하지 말 것 — STEP 3 핸드오프의 "직변환 차단 보고서" 줄이 그대로 전달한다
- **exit 1**(스크립트 자체 오류) → 비차단 경고만 기록 (직변환 차단은 STEP 4가 최후 안전망)
- `--allow-compound` 사용 금지

> **근거 (v10 실측 2026-06-11)**: 설계 결함이 STEP 4까지 내려가면 왕복 1회당 ~15분(CLI 부팅 3회). C-14는 설계자 게이트(Step 11.5) 누락/회귀 시의 2차 그물.

## 이슈 레벨 기준

| 레벨 | 기준 |
|------|------|
| CRITICAL | 파이프라인 진행 불가 (파일 없음, 분류 구조 없음) |
| HIGH | 설계 누락 → TC 품질 직접 영향 (커버리지 누락, 트리 없음) |
| MEDIUM | 서식/태그 누락 → tc-writer 작업에 영향 |
| LOW | 권고 수준 |

---

## Pass Gate

```
CRITICAL = 0  →  설계 수정(STEP 3) 없이 TC 작성(STEP 4) 진행
CRITICAL > 0  →  STEP 3 설계 수정 (최대 1회 재실행)
```

HIGH/MEDIUM/LOW 이슈는 design_review.md에 기록하되 STEP 3 트리거 조건 아님.
단, **HIGH ≥ 1건이면 STEP 3 트리거** (설계 누락=TC 품질 직접영향이므로 작성 전 차단). → needs_fix=true.

## step_result.json 형식

```json
{
  "status": "success",
  "issues": {
    "critical": 0,
    "high": 0,
    "medium": 0,
    "low": 0
  },
  "total_issues": 0,
  "analysis_gap": 0,
  "needs_fix": false,
  "review_path": "team/specs/[기능명]/design_review.md"
```

`needs_fix`: CRITICAL > 0 또는 **HIGH ≥ 1**이면 `true`. (Pass Gate와 일치)
`analysis_gap`: **C-13 HIGH 건수**(기획서→분석 누락 요소 수). `>0`이면 팀장이 STEP 3을 **opus 재분석**으로 라우팅(분석 패치 필요). C-13 외 HIGH(설계 이슈만)는 sonnet 설계수정 유지.
